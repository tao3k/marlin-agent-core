#+title: Marlin terminal client

The terminal client is an early interactive model-gateway surface inspired by
Codewhale. It does not yet execute tools or expose approvals or graph receipts.
It is not a coding agent. Model text is streamed
through Marlin's typed gateway interface; a truncated or rejected stream is
shown as an error and its partial output is excluded from later context.
Each turn's displayed model text is limited to 16 MiB in both persistent and
nonpersistent sessions. An over-limit chunk is rejected in full and the turn
fails; earlier partial text remains visible and is not added to model history.
The configured Weaver adapter checks this limit before accumulating each
emitted chunk, and the TUI checks it again before queue admission. These checks
do not bound provider decoding, the size of one upstream event, or total process
memory.

Completion responses are also limited to 32 MiB of accounted owned heap
capacity across metadata and all choices before journal cloning or UI queue
admission. An over-limit response is recorded as unresolved in a persistent
session; previously accepted streamed text remains provisional. This check
does not bound the provider decoder's earlier allocations.

Copy =example.toml= to a local configuration file and select the provider and
protocol. Credentials are not stored in TOML. For Anthropic-compatible routes,
an omitted endpoint is resolved by Weaver from =ANTHROPIC_BASE_URL=, and an
omitted model from =ANTHROPIC_MODEL=. Explicit TOML values take precedence.
Set the named credential environment variable. Local HTTP endpoints must use
a loopback address. Run =just tui-aot-debug= once after installing the selected
Scheme dependencies, then launch
=target/debug/marlin-tui path/to/config.toml=. The default TUI feature is
=linked-ui=: normal Cargo builds also produce the linked binary after the
selected Scheme programme has been staged. The Cargo build script reports a
missing staging manifest instead of silently producing a dynamic TUI.

The older dynamic loader remains available explicitly with
=cargo run -p marlin-agent-tui --no-default-features -- path/to/config.toml=.
It requires the compiled Scheme package and its SDK metadata; use
=GERBIL_PATH= and =GERBIL_LOADPATH= when the package environment is not the
default. From the repository root, when =GERBIL_PATH= is unset, this dynamic
executable restarts with =scheme/.gerbil= as its package prefix. Rebuilding
without default features replaces =target/debug/marlin-tui= with the slower
dynamic artifact; rerun =just tui-aot-debug= before measuring the linked path.

=just tui-aot-build= builds the selected Scheme package, compiles
=scheme/tui-entry.ss=, stages the programme from =init.exports.std-make-spec=,
and links the resulting graph with the VM into =target/release/marlin-tui=.
The =linked-ui= feature uses the SDK's =external-program= lifecycle and rooted
object ABI; the executable does not resolve a Gerbil package at runtime.
Optional external UI modules still need a separately qualified dynamic
extension path. The Darwin binary currently links system and package manager
libraries such as OpenSSL, zlib, SQLite and iconv; distribute those alongside
it where the target machine does not provide them. The build requires a paired
Gerbil/Gambit compiler and pkg-config metadata for these libraries.
Tab and Shift-Tab move focus forward and backward through the Scheme workbench.
An admitted Scheme extension may supply up to 16 =text= or =field= items, each
with strings of at most 256 characters. Focusing one displays its content in
the main window. The default workbench has no right-side Guide frame.
The selected Scheme module owns component composition and event methods; Rust
checks the typed snapshot, owns terminal rendering and authorizes effects.
The shared =marlin-agent-ui= library admits event/intent/successor agreement
before any renderer can act. The TUI adds command-handler and terminal-focus
admission; it maps keys and paints cells. =M-x help= shows the current shortcut
summary.
This is a bounded content slice, not a general dynamically loaded UI package
system. Sheprd may later consume the same Scheme publication and typed UI
projection through a separate client adapter. GPUI and Sheprd code do not
belong in =marlin-agent-core=, and Sheprd is not a =gerbil.pkg= dependency here.
In the transcript, Up and Down scroll; =M-x= or Ctrl-O opens command selection
while keeping the message draft. The command list appears beneath the Modeline
and Mini Buffer input line, with no separate command box.

The =provider= identifies the model provider; =protocol = "anthropic"= selects
the wire format, including for an Anthropic-compatible DeepSeek endpoint.
Optional =[anthropic]= settings select =thinking= (adaptive, enabled with a
budget, or disabled), =effort= and =max_tokens=; see =example.toml=. A named
model can use =[models.<alias>.anthropic]=. Weaver validates the settings and
encodes the request. Model and provider support for these options varies.
The Weaver dependency is pinned to PR #4 revision
=2cbb6bf7c6bcfddccde5105b809739323fa29d50=; it has not yet merged to main.
The Weaver adapter emits thinking fragments and retains Anthropic
continuation blocks. The TUI permits a follow-up only when observed thinking
and answer match the retained blocks; this checks consistency, not signature
authenticity. Replay shows recorded thinking in observed order and applies the
same check. Unmatched or missing continuation remains blocked. Thinking
controls are configured per route; durable Org persistence remains incomplete
and checkpoints are currently stored in the optional session database.

New provider continuations carry a sensitive fingerprint of the configured
destination, authentication mode, headers and credential. Changing any of
these rejects replay before dispatch; credential rotation therefore requires
explicit reconciliation. Older continuations without a fingerprint remain
inspectable but cannot be automatically continued. This fingerprint is not
proof of a server or account identity and can enable guessing weak credentials;
protect the session database accordingly. No reconciliation tool exists yet.

Optional =[models.<alias>]= entries configure additional explicit model
endpoints; see =example.toml=. =M-x models= lists the configured identities and
=M-x model <alias>= selects one while idle. The top-level model is =default=.
Selection survives session switches but resets to =default= on restart. The
next request sends retained conversation to the selected endpoint. A stored
OpenAI Responses continuation is restricted to its original logical model route;
selecting a different route warns immediately, as does restoring an
incompatible session. Submission is rejected before dispatch with the draft
retained; restore the original route or open another session. Older
messages may lack continuation data. The journal records the selected model
identity, but does not bind that identity to a particular URL across later
configuration changes. The current local Weaver validates Responses terminal
output against streamed text. Credentials are read at startup; a named model with a
missing credential is unavailable until the environment is fixed and the TUI
is restarted. Availability is not a network or provider health check. This is
an explicit user selection, not automatic model routing or policy admission.

Enter sends a message, Ctrl-N inserts a newline, arrow keys move in the draft,
Home/Ctrl-A and End/Ctrl-E move to the start and end of the current logical
line (even if it wraps),
PageUp/PageDown scroll output, Esc cancels a pending request and Ctrl-Q exits.
Alt-P and Alt-N browse earlier and later prompts from successfully completed
turns in the current session. Returning past the newest prompt restores the
original draft and cursor; sending a recalled prompt restores the draft as well.
Edits to a recalled prompt are discarded when navigating away. History browsing
is unavailable during active turns, command entry and read-only inspection.
In raw mode Ctrl-C also cancels a pending request or session switch, or closes
the command editor. When idle, the first Ctrl-C preserves the draft and arms
exit; the next consecutive Ctrl-C exits. Any other input disarms it. Cancellation
is local and does not confirm that a remote provider stopped.
On Unix, external SIGINT, SIGTERM and SIGHUP received while the terminal loop
is active trigger local cancellation, terminal cleanup and exit with status
=128 + signal number=. An unfinished persisted turn remains unfinished on
restart; no remote retirement is inferred. SIGKILL, terminal disconnection,
blocked output, suspension and job-control handoff are not covered by this
shutdown guarantee.
M-x or Ctrl-O opens the Mini Buffer command input while keeping the message draft
and cursor. Enter runs the command and restores the draft; Esc or Ctrl-O returns
without running it. The menu shows matching Scheme-declared command descriptions;
Up/Down selects a match and wraps through the list. Enter runs the selected
command or opens its argument input; Tab completes the selected command.
Without a selection, Tab completes an unambiguous command or adds a space after an exact command
that takes arguments. Commands are entered through M-x; the message editor
keeps its text as a model draft. Rust retains authority over
command execution. When a session switch succeeds, the draft is carried into
the selected session. Copy it before exiting the application.
=M-x help= shows the shortcuts and =M-x clear= clears the displayed transcript;
=M-x clear= does not discard the model conversation history. A failed or cancelled
turn stays visible but is not sent as part of the next request.
=M-x toggle-thinking= expands or folds the newest thinking segment;
=M-x toggle-thinking 2= selects the second newest retained segment, and so on.
The ordinal changes only visibility and is valid while a turn is streaming.
The selected Scheme UI displays a prompt as =› text=, a normal answer without
an extra role heading, and folded thinking as a single =▸ Thought= row.
Expanding changes it to =▾ Thought= with the original content below. Folding
changes only displayed rows: signed thinking, replay checkpoints, and the model
continuation retain their original content. M-x remains available while a
model turn is streaming and shows only the thinking toggle until it finishes.
The editor scrolls its visible rows to keep the cursor in view for longer
drafts. It wraps at grapheme boundaries, including on narrow terminals. Up and
down move by displayed row and preserve the desired column across short rows.
After drawing, transcript scrolling is clamped to the available rows for the
current terminal size. While reading older rows, tail-only output changes and
the waiting indicator are compensated so that the same row position remains
visible. The anchor resets on resize, clearing, or changes outside the tail;
it is a row position rather than a stable source-text position, so reflow of a
visible changed line can still move text. Closely spaced page keys may arrive
before the next draw clamps an overshoot. The anchor retains counts for
completed source lines and rescans the unfinished line and newly appended
lines; this does not establish a latency bound for a long unfinished line.

=M-x context-budget= reports completed-turn and next-request byte accounting against
the local admission limits. Use Ctrl-O to inspect the current draft without
sending it. These are accounted message bytes, not model tokens or total
process memory; the command is unavailable in read-only history views. Marlin
does not compress or summarize context here: retained messages are sent, and a
request exceeding the admission limit is rejected with its draft preserved.
This command reports a local request limit; it is not an ORG Context query or
an MRR evidence view. The short =context= command has been retired so it does
not imply those semantics.
Retention of provider-specific continuation data has the limitations described
above.

=M-x runtime= displays the typed runtime edge-policy receipt for opening a model
stream. Its timeout comes from =timeout_seconds=. The runtime edge timeout
applies only until the gateway returns a stream; it does not govern the length
of the stream, approve tools, or confirm remote cancellation.

=M-x status= reads Git status for the current working directory in the background
and displays index and worktree states, untracked entries and rename sources.
It uses Git's normal ignore and submodule configuration; it is a point-in-time
observation, not a snapshot or an authorization for changes. Git's optional
index locks and filesystem-monitor hooks are disabled for this read. A result
over 1 MiB or 10,000 entries, or taking more than 10 seconds, is rejected in
full. Esc or Ctrl-C requests local cancellation. Paths are escaped for display;
the status is not added to the model conversation.

Successful workspace reads appear in a separate view starting at the top;
PageUp/PageDown scroll it, and Esc or Ctrl-C returns to the conversation while
retaining the draft. Submitting a new command or message also closes the view.
Only the latest workspace result is retained and it is not saved to the session;
run the command again to refresh it. While a workspace read is pending, new
submissions are held in the editor. Short progress and error messages still
enter the transcript; this does not bound total transcript or process memory.
The workspace view lays out from the top through the requested visible rows;
deep scrolling still traverses preceding content, and oversized individual
graphemes and rendering allocations have separate costs.
Git output conversion and view construction run on a background Tokio worker.
Cancellation returns locally, but synchronous conversion already in progress
may continue until it completes. Another workspace read is refused until that
task has retired. Conversion still uses memory and occupies its worker.

=M-x diff= shows unstaged tracked changes (worktree against index), and =M-x diff
staged= shows staged changes (index against HEAD). Git presents renames as
deletions and additions; binary files follow Git's normal binary-diff summary.
Untracked files are listed by =M-x status= and are not included in these diffs.
External diff programs, text conversion and color are disabled. The same
1 MiB and 10-second limits apply; over-limit output is rejected in full.
Control characters are escaped and the output is not sent to the model.
To select a path, use =M-x diff "path/to/file"= or =M-x diff staged "path/to/file"=.
The argument is a JSON string relative to the repository root even when the
TUI starts in a subdirectory; Git matches it literally, not as a wildcard.
Absolute paths and parent-directory components are rejected. The command
accepts UTF-8 paths; non-UTF-8 names can be listed by =M-x status= but cannot
currently be selected here. An empty diff can mean the path is absent or
untracked. Selecting a directory can include its tracked descendants. A
selected result that exceeds the limit is still rejected.

With a persistent session configured, =M-x sessions= loads up to 20 session IDs
in the background and =M-x sessions next= loads the next page. The current ID is
marked. Use either form when no model turn is active. IDs longer than 512
bytes are omitted from the terminal list; use the command-line listing to see
them. Listing does not prove that a session is safe to resume.

Use =M-x session "session:another"= to switch while no model turn is active.
The ID is a JSON string, matching the quoted IDs shown in the list. Loading
happens in the background; the current session remains in use if loading fails.
Esc cancels a pending switch. Switching away from an unfinished turn does not
finish, recover, or retry it; selecting it again still shows the saved prefix
and blocks new turns.

Session loading rejects histories exceeding 10,000 turns or 64 MiB of accounted
projection data. It does not silently shorten the model context. This is not a
total-memory limit: storage pages, individual records, current live history and
terminal data have separate allocations.

Use =M-x inspect "session:another"= to view history without loading it as model
context. Each page retains at most 100 turns and 8 MiB of accounted projection
data; a single larger turn is explicitly marked as omitted, with its source
unchanged. =M-x history-older= loads the preceding page and =M-x history=
returns to the latest. Each page rescans the complete journal, so cost grows
with history size; separate pages do not share a snapshot. Model requests are
disabled while inspecting, and the draft is retained. =M-x session= can exit
inspection only if the complete context can be loaded. To inspect a session
too large to load at startup, start with another session ID first. Starting the
TUI currently still requires model configuration and credentials.

Session loading checks the event count before and after paging and rejects an
inconsistent scan. This assumes append-only, consistently visible local
storage; it is not a database snapshot or an ownership lease. A busy session
may need to be reopened after concurrent writes stop.

To opt into a local conversation journal, add a session to the configuration:

#+begin_src toml
[session]
path = "/absolute/path/to/conversation.db"
project = "project:example"
session = "session:example"
agent = "agent:example"
#+end_src

Completed turns are replayed when the same database and identifiers are
opened again. The start is stored before contacting the provider, and the
observed outcome is stored before the interface receives it. Cancellation or
an uncertain write blocks further submissions until the session is reopened.
An unfinished turn remains blocked after reopening: the prior process or remote
request may still be active, and there is no ownership recovery command yet.
Stream-open timeouts and Weaver transport failures are stored as typed
uncertainty observations: a provider may have received the request, and the
session remains blocked after reopening. Stream transport failure, timeout,
invalid or incomplete provider response, and a missing terminal event are also
recorded as uncertainty; the observed uncheckpointed prefix is saved before
the observation. Invalid chunk order or size, a local or provider byte limit,
and an inconsistent completion are also treated as uncertainty; rejected
output is excluded from the saved prefix. If either write fails, the turn
remains unresolved and the
write result is not assumed. The session also relinquishes write authority
while checkpoint or terminal storage is pending; cancelling that write cannot
silently restore authority. Other errors observed after the stream opens are
also recorded as unresolved, without retaining their original diagnostic.
Unclassified stream-open errors are also unresolved. Only a typed rejection
that establishes the request was not dispatched permits another turn.
Historical failures already stored by older versions are not automatically
reclassified as uncertain. Legacy locally cancelled records are also replayed
as stored; neither historical record proves that a remote request retired.
Sessions containing either record are read-only for new turns until a future
reconciliation mechanism can establish retirement. Later stored turns do not
by themselves establish that earlier remote work stopped.
Weaver currently maps malformed responses and some provider-reported failures
to the same response error, so that category is handled conservatively.
An inconsistent completion can also represent a provider that has already
finished; without a trustworthy completion, the session still stays blocked.
Transport failure is treated conservatively even if a connection may have
failed before dispatch, because this boundary cannot distinguish that case.
The first nonempty streamed fragment and subsequent accumulated batches of at
least 64 KiB are checkpointed. When the stream is actively polled, a smaller
pending batch is also attempted after one second. This is not a persistence
deadline: backpressure, scheduling, storage or process failure can delay it.
After a crash, the last uncheckpointed tail may be lost; a recovered prefix is
shown without automatically retrying the turn.
Without this section, history is temporary and exists only for the current
process.

Use =marlin-tui path/to/config.toml --session session:another= to select a
different session in the configured project and database. A new ID starts an
empty conversation on its first request; an existing ID replays its history.
The selected ID appears in the transcript. Selecting a new session does not
resolve or retry an unfinished turn in another session. This requires a
=[session]= storage configuration.

Use =marlin-tui path/to/config.toml --list-sessions= to print a JSON page of
session IDs with recorded events for the configured project and agent. If
=next_cursor= is not null, request the next page with =--list-sessions --after
<session-id>=. The list is ordered by ID, not recency, and does not assess
whether a session is safe to resume. Sessions with no events are not listed;
events may belong to other Marlin surfaces. Listing does not require a model
credential or a terminal. It opens the existing local database using the normal
storage initialization path, which may initialize an index.

On terminals that support bracketed paste, a paste is inserted as one editable
draft, with CRLF normalized to LF. The total draft is limited to 1 MiB of UTF-8;
an insertion that would exceed the limit is rejected in full, the draft stays
intact, and the status line reports the rejection. Delete text to make room.
A paste is never submitted by its own newlines. Terminals that send unbracketed paste as ordinary key events
cannot yet provide this guarantee; avoid multiline paste on those terminals.

Before each model request, the TUI checks the complete model context and next
prompt against 10,000 turns and 64 MiB of accounted message data. An over-budget
request is not sent, no prior history is truncated, and the draft stays in the
editor. Ctrl-O allows switching sessions without clearing the draft; copy it
before restarting. The budget applies at
admission: a successful response can push retained context above it, in which
case a later request is blocked. It does not bound total memory, live transcript
data or journal event count.

Request preparation normally clones the complete conversation on a background
Tokio worker. If cancellation overlaps a still-running preparation, a later
history update may also trigger a copy on the terminal thread. Copies still use
memory and occupy their executing thread; this is not a total-memory or latency
guarantee. Cancellation remains local and does not prove remote retirement.

* OpenTelemetry traces

Set =OTEL_EXPORTER_OTLP_TRACES_ENDPOINT= to a full OTLP/HTTP protobuf traces
URL such as =http://127.0.0.1:4318/v1/traces= to enable =marlin-agent-telemetry=.
The TUI sends Runtime lifecycle spans under service name =marlin-tui= and
shuts down the exporter after Runtime drain. The selected span target carries
lifecycle classifications. Process-registry events, terminal content, metrics,
and log records are outside this export.

* macOS Runtime process budget and host observations

The optional =[process_budget]= section in [[file:example.toml][example.toml]]
passes Runtime its own typed configuration. Choose concurrency, the admission
limit and the per-command reservation for the machine and tool mix. Runtime
uses the reservation for every managed process. The telemetry package samples
the host and registered direct children locally, even with OTLP disabled.
Runtime releases the reservation after process cleanup and closure of its
managed pipe leases.

Set =MARLIN_TUI_HOST_OBSERVATIONS_FILE= to a new local file path to start the
independent macOS observer. The file records terminal and Tokio heartbeats
and kernel-confirmed host exit. The observer only reports evidence. The
Runtime owner remains responsible for cancellation and process reaping.

Use =M-x list-processes= to open =*Processes*=. It shows the current session's
live Runtime processes and recent terminal results. Use =M-x kill-process=
followed by the generation number in the first column. Runtime resolves that
generation to its owned process and runs cleanup. The PID column is for inspection.
