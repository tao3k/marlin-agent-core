=gerbil.pkg= declares AI Agentic Lab as the sole direct package dependency.
Cargo selects the Scheme bridge used by Rust and the linked programs.
Lab's =core= submodule fixes Yuanxu's exact revision. Lab supplies the POO contracts, and the Context and Session
implementations. =init.ss= selects =context +causal=, =ui-components=, =ui=,
=hooks=, =policy=, and =deck-runtime=. A package-backed Lab window explicitly selects the upstream
Context Module; Marlin Context requires its qualified identity.
=context/types.ss= reuses Lab's =AiAgenticContextScopeType= for the input and
output of the admission function. The typed decoder constructs the Lab Scope
prototype, and =context/objects.ss= publishes Lab's admission procedure.
Lab owns the Scope invariants and the returned scope digest.
The =+causal= Feature publishes solve and replay operations over Lab's
Temporal Causality exchange. It returns the original ASCENT answer with its
receipt and verifies replay against the caller's exact exchange.

| Role | Responsibility |
|------+----------------|
| =context/= | Adapt Lab's Context library to Marlin's runtime boundary. |
| =ui-components/= | Publish component prototypes, bounded constructors, Guide and the POO-composed command catalog. |

| =c-abi/= | Own the C entry points and their bindings. |
| =t/= | Exercise policy composition, projections, and receipt fixtures. |
| =bench/= | Own the optional SDK-linked mailbox qualification workload. |

Each module publishes its scope through =interface.ss=. The contract, objects,
and validation live in =types.ss=, =objects.ss=, and =config.ss= respectively.
Yuanxu owns Module selection, Feature refinement and option contracts. Deck
Runtime creates a Gerbil mailbox Actor on first use of a logical Context
identity and reuses it across turns. Each completed message carries its ID,
status and Scope digest, independently of unfinished Actors. The owner closes
the service explicitly. Rust maps the version from the published Scheme
=metadata= record. The Deck C ABI roots the selected runtime roles in the
compiler graph; Yuanxu retains checked publication and Feature selection.

Gerbil compiles the C link units through Gambit and executes policy in the
Scheme VM. The Rust adapter owns typed requests, authorization, and receipts.
=marlin-agent-context= owns the typed Rust request and prepares a bounded
batch for the owner-local C ABI. =context/batch.ss= adapts the batch to the
published Context operation, and =c-abi/context-admission.ss= exposes the
entry through gerbil-scheme-rust's rooted-object ABI. The batch transfers
shared fields once and returns an ordered array of Lab scope digests.
The =actor-runtime= feature links the single-VM image and submits owned
Context/Session requests. Wiring a live TUI conversation to its authoritative
Session binding remains integration work.

Install the package dependencies with =just scheme-deps=. CI activates the
bridge's SDK action. On a dependency cache miss, CI uses =gerbil build= on
Cargo's selected bridge to provide the tools used by Orgize's Builder, then
runs =gerbil deps --install= in Marlin's Scheme package. Run
=just scheme-package-gate= to initialize the VM and call
=GerbilRuntime::build_package= and =GerbilRuntime::test_package=.
The platform workflow builds the Yuanxu-selected Scheme package once per
runner platform. Rust checks, tests, Scheme ABI checks and linked AOT jobs
restore that run's package artifact. The Context test calls the Lab-backed
Scheme Org interface through typed Rust values. The TUI job stages its linked
program from the shared package. Rust workspace checks that still consume
Orgize directly use the parser program built during Scheme dependency install.
The cross-run Scheme cache stores the installed dependencies before compiling
Marlin modules. Its key includes the runner architecture, SDK and host
toolchain identity and dependency locks.
Each Rust job caches its own Cargo build artifacts and runs its checks on
the current checkout. App Server HTTP/2, Quint, formatting and REUSE can
start independently of Scheme preparation.
CI sets =GERBIL_BUILD_CORES= to each runner's available logical CPU count
before activating the SDK. Dependency builds, the package Builder, and Rust's
embedded package build receive the same worker budget within a job.

The pinned Lab revision installs source declarations without eager library
compilation. The package window in Marlin INIT gives Yuanxu the upstream
source ownership needed to derive the combined library closure. The Context
Module publishes its bounded bridge projection through its typed contract.
=build.ss= hands the =std-make-spec= exported by =init.ss= to the native
=defbuild-script= through Yuanxu's admitted build consumer, with =init= as its
explicit root. The compiler consumes Yuanxu's checked cross-package source
view. The selected =c-abi=
Module contributes its own adapter inputs through its Build role.
The project direnv configuration and Justfile default =GERBIL_BUILD_CORES= to
the number of online processors when it is unset; an existing value is preserved.
The pinned SDK's embedded package-build path also preserves an explicitly set
value, and defaults to the CPU count only when the variable is absent.
The full Scheme test fixtures additionally import Lab constructors outside
the production closure. Put the pinned Lab source checkout on =GERBIL_LOADPATH=
for that test invocation; CI does this without adding test modules to the
production library. If a direct =gxi= aggregate run reports a missing
