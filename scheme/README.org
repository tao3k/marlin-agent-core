#+title: Marlin Scheme Package
#+language: en

Marlin's Gerbil package owns Module selection and Scheme policy. It supplies
Context and Org integration, the UI declaration plane, hook and graph
policy, and the Scheme side of the runtime boundary. Start with the
[[file:CODING-STYLE.org][Functional Scheme coding style]] for module authoring.

* Package and module selection

=gerbil.pkg= pins AI Agentic Lab as the direct Scheme dependency. Lab supplies
Yuanxu and the Context, Temporal Causality, and GitOps capabilities. The
package-wide =interface.ss= imports their public declarations. =init.ss=
selects Marlin's Modules and their Features through =yuanxu!=, including
=context-system +causal= and =gitops +worktrunk=.

A Module's =interface.ss= publishes its roles. Consumers use the selected
namespace under =marlin-agent-core.init.exports=. Configuration composes
operations and validates the published scope. Ordinary Scheme functions
handle values. POO prototypes carry defaults and extension points.

* Build and test

Run these commands from the repository root.

#+begin_src sh
just scheme-deps
just scheme-build
just scheme-package-gate
#+end_src

These recipes use the official Gerbil package commands. When working inside
this directory, =gerbil build= runs the package's =build.ss=. The entry
passes the =std-make-spec= selected by Yuanxu to Gerbil's =defbuild-script=.
The C ABI Module supplies its link options through the existing =with-link=
slot. The build publishes products for the selected =program-entry= roles.
Use =just scheme-clean= to run =gerbil clean= with the same toolchain settings
as =just scheme-build=. It removes the package's selected compiler outputs
and its published link products.

Use =just scheme-test t/ui-workbench-test.ss= for a focused UI test.
=just scheme-property-gate= also exercises the native UI Scheme suite.
Use =just scheme-ui-package-gate= for the independent UI package through the
Rust-owned VM and =just scheme-ui-abi-gate= for the rooted C ABI fixture.
Native fixtures under =t/= are test inputs. CI supplies the selected Lab
test dependencies with the same installed package environment used for the
build.

* Rust and Scheme

Cargo pins the Scheme SDK at the Rust boundary. Gerbil compiles the selected
Scheme program and publishes its link products. Cargo consumes those products
from =GERBIL_LOADPATH= and links them with the SDK ABI carriers. The Scheme VM
executes the Scheme operations after startup. The Rust host owns typed
configuration, native effects, and receipts.

=just tui-aot-debug= runs the Scheme build and links the default debug TUI.
For a direct Cargo invocation after =just scheme-build=, set
=GERBIL_LOADPATH="$PWD/scheme/.gerbil/lib"= from the repository root.

The =t/= directory contains the Scheme test entrypoints and fixtures. The
=bench/= directory contains the opt-in Context and Deck Runtime workloads.
