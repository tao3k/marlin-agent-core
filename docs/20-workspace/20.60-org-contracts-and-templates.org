#+title: Org Contracts and Host Projections

* Semantic owner

Scheme Orgize owns Org Contract declarations, queries and evaluation. Lab
Context composes the selected profile and exposes source cuts. Marlin Rust
consumes typed results through its existing Scheme VM; it does not depend on
the Orgize Rust crate or maintain an AST evaluator.

See [[file:../40-rfcs/40.181-context-org-ownership.org][Context-owned Org architecture]] for the public boundary and limits.

* Host projections

Rust's =RenderedContractFacts= and workspace status retain producer-supplied
registry, reference, diagnostic, template and validation records as data.
=MemoryOrgWorkspace::apply_projection= accumulates those records with typed
nodes for local query/view use. It preserves producer outcomes, including
failed and skipped receipts. It does not execute contract assertions.

Parser-defined fields and source semantics remain behind =ContextOrgModule=.
Source IDs, generation, parser identity, digests and byte spans cross as typed
values. Rendered summary text is a display projection, not a receipt parser or
an authority source.

* API migration

The former =OrgDocumentLoader=, Rust contract discovery and evaluation adapter,
automatic raw-document store queries and Rust built-in standard-contract
library have been removed. Consumers must use the selected Scheme package.
The old Workspace patch packages and mutation receipts are also retired;
there is no source-mutation fallback here.

A Contract source cut is not a durable commit or an authorization to act.
Runtime effects still require the host's current-use admission and typed
execution receipts. The remaining file store performs individual replacements;
a transactional Org turn journal remains separate integration work.
