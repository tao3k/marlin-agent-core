#+title: Marlin declarative terminal interface

* Objective and reference

Build Marlin's own terminal interface, informed by Codewhale's TUI at
=b8643a76e417c4fbc55251be1308cdb6862a80f5=.  The reference checkout lives in
=.data/Codewhale= and is not a build dependency.  Codewhale is MIT licensed;
any copied material must retain its required notices and third-party attribution.
The reference is evidence for capabilities and engineering problems, not a
visual identity or an instruction to reproduce another application's design.
Marlin's own Scheme extension model, runtime ownership and workflows define
the resulting product.

Marlin remains the owner of execution, policy, configuration, typed receipts,
and evidence.  The interface must not fabricate an agent response, approval,
tool outcome, or a successful action when the backing capability is absent.

* Initial observations

Codewhale's TUI spans a large product surface and depends on its own engine,
protocol, runtime and many other crates. Copying it wholesale would introduce a
second authority model. Marlin currently describes its =marlin= executable as a
harness/debug surface, and its typed model gateway, graph execution and runtime
receipts are separate building blocks. A terminal shell must integrate those
blocks rather than treating the existing debug CLI's JSON output as its protocol.

** Startup and hybrid execution decision

The current =run= validates configuration, initializes the Scheme VM, resolves
the package publication and opens the Scheme UI before entering terminal raw
mode or drawing a frame. It cannot present a responsive workbench during that
interval. The pinned SDK documents package export resolution as a startup
operation that must not overlap unrelated environment or subprocess work; it
also checks the VM owner thread. Simply spawning the current resolver beside
the input/Tokio threads would violate that contract.

The desired lifecycle separates (1) process start to a responsive terminal
initialization state, (2) Scheme UI readiness and admission of its actions,
and (3) terminal restoration and VM retirement. The design target is subsecond
first interaction and Scheme readiness within a few seconds. These are target
budgets, not measured results or replacements for the existing strict
ten-second workbench and five-second exit tests. Initialization must visibly
report pending, ready or failure, support cancellation and restoration, and
never route Scheme-dependent actions before readiness. A fast loading screen
alone is not a fast usable UI.

The selected core is now linked into the Darwin Release binary, and the
source-free PTY gate covers UI publication, first frame and normal exit. The
earlier 65 ms VM-only control did not cover the selected UI; it remains a
historical control rather than product evidence. The Release startup spread
requires a controlled cold-process study before deciding whether lowering
Scheme work is useful. The application-internal first frame is already far
shorter than the slow process-to-observation samples; attribution of that gap
requires process and terminal measurements. If the full linked Release misses
the cold budget, profile the remaining work before restoring the removed IR.
The possible lowering
scope then includes macro-expanded code and object/generic dispatch where they
actually dominate, not just pure string functions. Any hybrid must preserve
selected Module identities, method precedence, errors, extension behavior and
typed boundaries. Runtime data crosses as Scheme and Rust types; the old JSON
build interchange is not a runtime protocol.

For each candidate, capture independent fresh-process cold and warm runs on the
same machine and terminal: process-to-first interactive state, process-to-UI
readiness, VM initialization, publication selection, first open, cleanup,
CPU, allocations, RSS, source reads and dynamic images. Hold package revision,
selected modules, input, extension set and retirement behavior fixed; report
individual observations, distributions and failures. Attribute macro-expansion
cost only with direct instrumentation rather than inferring it from elapsed
startup. Include missing/substituted module and extension-dispatch controls,
as well as terminal restoration when initialization fails or is cancelled.

** Proposed Scheme UI extension plane

The client now has a selected Gerbil/Yuanxu workbench with declared regions,
focus order and CLOS event methods. Rust still paints the terminal, and a
general plugin lifecycle, richer stateful widgets and module admission
remain open. The current bounded text and field content slice is described
below. The target extends that Scheme module so components, keymaps,
composition and state transitions are authored as Scheme values.
Rust owns the terminal, input decoding, layout and Ratatui painting, async
I/O, typed runtime commands, and effect authorization. Model/session facts and
receipts originate from their existing runtime owners, never from a UI plugin.

The linked TUI executes Scheme in the Gerbil/Gambit VM. Gerbil and Gambit
compile and link the selected module closure for that VM; the SDK package named
=gerbil-scheme-aot-build= builds the linked program archive. Neither that
package name nor the =tui-aot-*= recipes imply translation of Scheme modules to
Rust. Scheme-to-Rust IR is a separate, currently unused backend with its own
limitations; linked modules do not by themselves establish dynamic loading.

The Scheme module, the Rust/Scheme calling boundary, and any AOT compilation or
linking step are distinct responsibilities. The module must not import an AOT
builder or require its host to use one image format. A native ABI adapter can
export typed, rooted Scheme values, but C ABI describes the call convention;
it does not itself establish a loader, a build policy, or authority. AOT is one
possible packaging strategy, not the definition of the UI extension plane.
Likewise, a Scheme VM must not be represented as already having dynamic module
loading solely because the language or a subprocess toolchain can load Scheme.

At the proposed =gerbil-scheme-rust= PR #18 pin =b3b50f0=, =GerbilRuntime::initialize=
provides the process-global native runtime, while =bind_object_export= requires
a function already belonging to that runtime's AOT graph. The SDK's package
build/main entrypoints and separate toolchain subprocess APIs are not a typed
live-module invocation API. An SDK-owned, typed module resolution and call
capability must therefore be established and qualified before the UI can rely
on runtime-loaded Scheme modules. Do not invent a Marlin text/eval protocol,
start a second VM, or present an AOT-only adapter as a general dynamic loader.
The actual implementation may support multiple execution or packaging modes,
but each needs a proven owner, lifecycle and typed value boundary.

The initial =scheme/ui= module publishes POO component and event prototypes,
declarative CLOS method bundles and a bounded workbench projection. It is
selected and exported by the same Yuanxu =init.ss= as the other Marlin modules;
module management and publication do not depend on a separate UI entrypoint.
The UI projection is a dependency of the selected UI module and is published
as an operation of that module. The selected =c-abi= Module owns its Deck and
UI adapter build inputs in its Build role; the adapter receives the complete
selected Yuanxu publication and derives its UI child, rather than importing
=init= or constructing a default scope. The Rust UI package resolves and retains
the selected publication through the SDK's package-export API.
The selected =c-abi= scope receives its UI, Context and Deck dependencies from
the Module System; membership checks retain the linked objects instead of
wrapping their function contracts again. The Scheme event generic produces
submit, dismiss and scroll intents, and accepts a bounded caller-supplied focus
order so component extensions can participate without editing the core focus
methods. The workbench also accepts explicitly supplied POO extension regions,
checks their identities and focusability, and derives a focus event from its
composed regions. The native projection preserves their labels and focusability.
The terminal renderer can paint these bounded labels and follows the focused
extension when vertical space is limited. It sanitizes control characters and
preserves transcript and composer space. The selected Modeline takes one row
when space permits; host status contributions appear in the collapsed Mini
Buffer. This is a presentation primitive, not
plugin discovery or general extension event handling: Enter may dispatch a
contributed submit method only to produce an admitted focus change; it cannot
submit the user's draft. The current TUI opens its session with no extension
contributions or method bundles.
An ignored, toolchain-dependent Rust test builds a test-only Gerbil package
through the SDK, resolves its contributed object and CLOS bundle in the same
VM as the selected UI, and routes Tab and Enter through the terminal host. It
also checks that an extension's forged draft-submission intent is rejected
without replacing the admitted state. This verifies that fixture path, not
production plugin discovery or complete plugin lifecycle authority.
The UI ABI opens a Scheme-owned session from the selected publication, typed facts and
an ordered vector of at most 16 Scheme CLOS method bundles. It composes those
bundles on a fresh unpublished generic; an invalid bundle aborts session creation
without changing an existing generic. Bundle protocol checks belong to Yuanxu's
CLOS implementation. The vector limit is not a bound on the size of an
individual bundle, and supplying a bundle is not proof of Module ownership.
The session retains the workbench, generic and focus under an SDK strong root. A typed
event produces a new session and intent; the old session remains valid. Scheme
derives the focused component and event from that session, checks focus order,
and rejects a focus result outside the workbench. These are consistency checks,
not proof that the supplied scope was selected by the Module System.
The dedicated =marlin-agent-ui= Rust package resolves the selected publication and the
open, project and dispatch procedures through the SDK's package API, calls the
rooted procedures through its C ABI, and converts rooted vectors,
symbols, strings and booleans through the SDK into Marlin UI types. It checks
the projected shape, built-in ordering, sizes and duplicate identifier spellings;
the result remains a candidate, and an intent is not effect authorization.
A typed Rust facts request now uses the same SDK to construct a rooted request
from the supplied scope, display facts and ordered extension vectors. Host labels, status identities and
outer contribution counts are checked before allocating the request; the SDK
roots do not establish scope or extension provenance.
When the model or session changes, the terminal host sends bounded labels as
Scheme strings through the same rooted SDK interface. Scheme constructs a new
workbench without an accumulating prototype chain; Rust admits it only if the
requested labels match and the existing regions and focus remain unchanged.
Unchanged labels do not trigger a VM call. Real-VM tests cover old-state
retention, bounds, and an extension method after a label refresh; they do not
establish complete provider/session switching acceptance.

One event cycle delivers typed input and an immutable view of the relevant
runtime state to the Scheme owner. The module returns a typed component tree
and typed intents. Rust validates the result, admits intents through their
owning runtime APIs, and paints the admitted tree. The native boundary projects
Scheme types into Rust types; it is not a JSON, Org, or Scheme-text protocol.
Stable domain identifiers, explicit focus ownership and versioned component
identity permit incremental updates and state retention without depending on
object addresses. Layout constraints, text, lists, panels, editor and overlays
are capabilities to specify through that contract, not Scheme wrappers for
each Ratatui method.

Extensions register through the existing module system, with explicit ordering,
key binding conflict handling and declared capabilities. A failed module or
invalid projection must remain visible as an error and cannot produce effects;
the last admitted UI state and terminal restoration remain Rust responsibilities.
The design must not imply that arbitrary in-process Scheme is sandboxed: the
actual trust and isolation properties depend on the VM and host capabilities.

The implementation must establish VM ownership and scheduling from the actual
runtime, bound event and projection size, batch crossings at a component/update
boundary, and cache unchanged visible subtrees. No per-cell Scheme callback or
unbounded event channel is a target. Benchmarks must compare matched terminal
sizes and input/output loads, including long streaming output, resize, idle,
slow extensions and allocation/latency across the native boundary. These are
requirements, not measured performance claims.

First deliver a vertical slice: publish a Scheme-owned workbench with a
transcript region, composer and extension-contributed status component; drive
real keyboard input through the native ABI to a Rust Ratatui frame and exercise
registration, focus, resizing, failure and cleanup in a pseudo-terminal. Then
migrate session navigation, model selection, menus and other Codewhale UI
features on the same contract. Runtime-dependent approvals and tools require
their real typed runtime capabilities before they can be interactive.

The in-memory session backend maintains per-project/session event counts under
the same mutex as event insertion. Replay's before/after count checks therefore
use an indexed lookup instead of traversing all events in that session. Batch
validation precedes index updates, so a rejected batch does not increment the
count. This is an algorithmic change to the in-memory backend, not a measured
end-to-end improvement or a change to Turso or the planned Org backend.
The storage unit suite passed seven tests, including cross-project and
cross-session counts and a rejected atomic batch that leaves counts unchanged.

The readiness receipt encoding now includes its evaluated required symbols.
Older serialized receipts lacking that field are rejected and must be
regenerated from the original runtime readiness check; counts alone cannot
establish the symbol identities.

The AgentGraph execution-request builder also checks nested readiness evidence:
the request, planning, projection, admission, timestamps, selected plan and
root loop entry must agree before a request is produced. This checks consistency
of supplied receipts, not their authenticity or the continued availability of
the referenced runtime graph.

These observations do not establish a comparative performance result or imply
that all reference-project features have been examined. In particular, a
bounded queue must not discard a denial, completion, or other semantic receipt
to satisfy a memory limit. Display coalescing is distinct from event retention.

** Qualification plan

Use the same terminal dimensions, fixture content, chunk timing, build profile,
machine, OS, sampling method, and offline provider for each paired comparison.
The primary comparison is an exact, frozen Marlin baseline against a Marlin
candidate; a Codewhale comparison is a separate optional observation, not the
definition of success or a requirement to match its interface. Record the
exact Marlin revisions and dirty patch identities and, when comparing the
reference, its revision =b8643a76e417c4fbc55251be1308cdb6862a80f5=. Warm up, run
multiple paired repetitions and retain raw observations, failures, and p50,
p95, p99 and maximum where meaningful. Report CPU time, allocation count and
bytes, peak RSS, bytes read and written, queued bytes, redraw count, input to
visible-frame latency, first-chunk to visible-frame latency, and cancellation to
runtime retirement latency separately; never substitute component timing for a
full user-visible measurement.

Scenarios include an idle terminal; 1k, 10k and 100k transcript rows; bursts
of short and large Unicode chunks; bounded slow-consumer overload; resize and
scroll during streaming; large paste and multiline editing; failed and
cancelled turns; and cold and warm session resume. Verify ordered delivery,
no duplicate replay, correct viewport, grapheme boundaries, no lost terminal
receipts, and restored terminal state in the same scenarios. Record retained
and transient memory separately and use a real pseudo-terminal for end-to-end
latency, while deterministic render and queue tests isolate mechanisms.

Quantitative thresholds are not yet accepted: first collect baseline
distributions and workload sizes, then choose explicit budgets and regression
limits with the user. A local green test, SysML validation, reference project's
historical claim, or a single run does not establish high-performance parity.

** Stream-open uncertainty (2026-11-11)

The runtime edge timeout and Weaver's typed open-stage timeout or transport
failure now produce typed unresolved observations rather than a completed
failed turn. The session journal appends an explicit uncertainty event and
retains the turn as unfinished; a failed uncertainty storage write relinquishes
local authority because its commit status is unknown. Replay preserves the
reason and blocks further turns. A local PTY fixture confirmed that a provider
which had already received a request but did not respond is not contacted
again after timeout and restart. This does not establish remote cancellation
or a general exactly-once contract. After the stream opens, transport loss,
timeout, invalid provider responses and missing terminal events are also
recorded as unresolved; the observed pending prefix is checkpointed first.
Invalid chunk sequence or size, local and provider byte-limit rejection, and
an inconsistent completion now follow the same typed unresolved path; the
first rejected chunk is not added to the persisted prefix. A malformed
completion is treated conservatively even if the provider has actually stopped.
Failed checkpoint and terminal writes relinquish local authority. Any otherwise
unclassified error observed after stream open also becomes a typed unresolved
observation; its original diagnostic is not retained by this path. Generic
errors during stream opening are also unresolved unless the gateway explicitly
reports that no downstream request was dispatched. Model-catalog rejection and
edge readiness failure provide that local evidence. The unclassified error's
original diagnostic is not retained. Historical failed events are not reclassified.
When a pre-dispatch rejection reaches the TUI (after its journal observation is
recorded in a persistent session), it restores the submitted prompt if the composer is empty; otherwise
it preserves the new draft and the visible rejected prompt. The session can
accept another turn. A rejection-labelled event from an already opened stream
is treated as uncertain, and a failed terminal journal write does not release
the session. These behaviors do not reconcile an incompatible continuation.
The journal's terminal-write API accepts only completion or a pre-dispatch
rejection, and rejects a pre-dispatch rejection after a checkpoint. Legacy
failed and locally cancelled terminal records remain readable with their
historical semantics; replaying them does not establish remote retirement.
Their presence now blocks new journal claims, even when later historical turns
exist. They remain inspectable, but there is no reconciliation command yet.

** Current TUI

For long logical lines at the live tail, the renderer can now retain a bounded
ring of visible row slices and scan once instead of twice. It limits retained
slice capacity to 16384 entries and falls back to the previous two-pass path
when the slice or viewport budget is exceeded; a slice-budget overflow may
therefore add a partial scan before fallback. Tests compare it to the previous
layout, including Unicode and fallback cases. A same-process debug-build
component diagnostic for a 250000-byte line at 80x12 measured eight paired
samples: the previous path took 140083–429368 microseconds, the new path
67763–123652 microseconds. This is not a full TUI, release-build, or sustained
streaming benchmark. Layout still scans a changed line, and a narrow CJK
fixture produced different wrapping from Ratatui's full renderer; the optimized
path preserves Marlin's previous behavior rather than resolving that difference.

=marlin-agent-tui= now provides a terminal client for a configured Marlin
model gateway. Its first version has a grapheme-aware composer, multiline
input, transcript scrolling, request cancellation and terminal restoration.
The configured Weaver adapter also checks cumulative text before appending
each chunk to its completion buffer; its limit is explicit and optional for
other adapter users. The TUI checks cumulative model text before accepting each stream event in
both persistent and nonpersistent sessions, rejecting a chunk that would cross
16 MiB and keeping prior text provisional. A completion without chunks is
checked too. The journal and UI also reject completion responses over 32 MiB
of accounted owned heap capacity across metadata and all choices before journal
cloning or queue admission; the journal records the prefix and typed uncertainty.
The journal retains its independent persistence boundary. The UI
guards cannot bound provider decoding or allocations made before an event is
yielded, and do not provide a total-memory or runtime-retirement guarantee.
Before model dispatch the TUI also budgets the complete model history and the
next prompt against 10,000 exchanges and 64 MiB of accounted message data.
It rejects an over-budget request without cloning, dispatching, losing the
draft, or truncating history. Admission accounting includes message structure,
text and optional names, not allocator capacity or all request metadata. A
successful response can take retained history above the admission threshold;
the next request is then rejected. This does not bound total process memory,
transcript contents, or journal events, and the two 64 MiB limits for context
and replay account different objects.
Successful exchanges form the in-memory model context; failed and cancelled
requests are visible but are excluded from subsequent context. The interface
does not yet provide agent tools, approvals or graph receipts; local persistent
sessions are optional. A typed gateway stream now displays text chunks
before completion and includes only successfully completed turns in later
model requests. Interrupted partial text remains visible with its error.
The multiline composer follows the cursor across wrapped rows and normalizes
its position when edits join grapheme clusters. Home/End and Ctrl-A/Ctrl-E
move to logical-line boundaries even when a line wraps. A pseudo-terminal fixture checks
a completed-session prompt history round trip while retaining the draft and
isolating session context. Another fixture checks
a five-line pasted draft, cursor visibility and exact submitted text. Composer
layout still scans the draft prefix. Up and down navigate displayed rows while
retaining the desired column across short rows and respecting grapheme boundaries.
Ctrl-O opens a separate slash-command editor without consuming the message
draft. Submission, cancellation and unsuccessful switches restore that draft;
a successful session switch carries it into the newly selected session. The
draft is not persisted across application exit.
The session PTY fixture verifies that the carried draft is submitted with the
target session's full context and that read-only inspection blocks dispatch.
Its first cross-session assertion incorrectly expected an entire old answer in
the incremental terminal byte stream; after changing the synchronization to a
target-specific rendered fragment, the fixture passed.
Raw-mode Ctrl-C cancels an active local turn or session load, or closes the
command editor; when idle it arms exit and a second consecutive Ctrl-C exits.
Other input disarms exit, and the first press retains the draft. This does not
implement clipboard selection, remote retirement or shell job-control handoff.
Codewhale's reference has a richer selection/copy and
recoverable input-clearing priority; this implementation does not claim parity.
Local Unix PTY checks exercised two idle Ctrl-C presses and restoration of raw,
alternate-screen and bracketed-paste modes. The flood fixture also exercised
Ctrl-C during active SSE output in both persistent and nonpersistent sessions;
each observed local cancellation after 0.023 seconds in one run. These are
not latency distributions, remote-cancellation receipts, or platform-wide
qualification. A unit test confirms pasted ETX remains input data rather than
being interpreted as an interrupt key.
On Unix, signal handlers are installed before raw mode for SIGINT, SIGTERM and
SIGHUP. During the terminal loop, an observed signal stops local work, restores
terminal guards and returns =128 + signal number=. A local PTY sends each
signal while idle and checks exit code and terminal modes; a second fixture
sends SIGTERM during a persistent stream and verifies that the checkpointed
prefix reopens as unfinished and no second provider call is made. These checks
do not establish remote retirement, SIGKILL cleanup, disconnected-terminal
restoration, bounded shutdown latency under blocked output, or suspend/resume.
The composer caps the entire draft at 1 MiB UTF-8, including accumulated
ordinary keys and pastes. An insertion exceeding the remaining space is
rejected atomically, retains the draft, and displays a status message; deletion
allows editing to resume. This bounds draft text bytes, not process memory or
interactive latency. No matched worst-case latency measurement has been made.

** Independent layout and deep scrolling

The client now separates word layout and terminal-buffer drawing, and selects
at most the visible rows using a =usize= history offset. Tests exercise 200,000
rows of scrollback, a 150,001-character logical line, and a long line of Chinese
graphemes. A one-column view shows a replacement marker when a wide grapheme
cannot fit; the stored transcript remains unchanged. The layout adapts Ratatui
Widgets 0.3.2 word wrapping, with its license retained in the TUI crate.

One deterministic mixed-Unicode, two-column case panics in the pinned Ratatui
0.30.2 reference renderer; the independent renderer completes on the same
fixture. This is a local test of a particular dependency and input, not a claim
about every Ratatui version. When an upstream row would exceed the viewport,
the layout splits it at a grapheme boundary before buffer access. Common
non-panicking reference cases are compared cell-for-cell; this repair can
intentionally differ from the reference on unsafe rows.

The current client keeps one visible viewport and reuses it on an unchanged
transcript, pending state, terminal size and scroll offset. All transcript
mutations pass through a revision owner; a different transcript has a distinct
identity. The cache stores one viewport, not a copy of the history, with a 1 MiB
budget accounting for vector capacities, span structures and owned string
capacities. A viewport over budget is rendered but not retained. This is not an
allocator-level or process-memory limit: the current frame, temporary wrap
vectors, terminal buffer and stored transcript are outside that accounting.
Control characters are normalized one grapheme at a time during layout rather
than copying an entire line when it contains a control character. Consecutive
zero-width graphemes are grouped as borrowed source ranges in wrapping state;
the original text is preserved. An instrumented test observed at most three
pending segments at iteration boundaries for 200,000 zero-width graphemes. This
is a segment-count result,
not a byte or process-memory bound: the materialized visible row can still be
large, as can a single grapheme, and other temporary allocations remain.
It avoids layout on composer-only redraws. For deep scrolling in a transcript of
at least 256 entries, a width-specific index stores the cumulative row count
every 128 entries. The index is invalidated by an old-entry edit, transcript
replacement or resize; a tail append can update its row count incrementally.
The checkpoint vector is capped at 1 MiB. Histories too large for that cap use
the full scan path, so a failed index build is not repeated on every scroll.
The transcript remains the source of rendered text; each deep scroll still
layouts the suffix between its checkpoint and the requested viewport. Index
construction and width changes still visit the full history once.

** Event admission and control fairness

The current UI queues at most 64 model events and accounts their owned string
and choice-vector heap capacities against a 32 MiB semaphore. Gateway errors
retain their typed interruption and uncertainty reasons through queue admission;
owned error payload capacities count against the same budget. The transcript
currently formats those errors for display and does not retain a separate typed
failure projection. A permit remains
with each queued item until the consumer takes it; cancelling a blocked sender
releases its reservation. Oversized events become an explicit failed turn and
stop the producer. The original oversized payload is not durably retained, so
this does not yet meet the target requirement for durable terminal evidence.
The Weaver adapter splits large text deltas at UTF-8 boundaries into ordered
chunks no larger than 64 KiB. The event loop processes at most 16 model events
before checking terminal input; the input channel holds at most eight events.

The count and byte bounds apply to queues, not total process memory: the
upstream SSE decoder, one producer-side event, completion response, transcript,
history, and raw input decoder have independent lifetimes. A completion can
therefore still fail admission if its owned capacity exceeds the budget. The
limit on event count per iteration is not a time bound: layout of a very long
line can still delay cancellation. There is no runtime-owned cancellation
retirement receipt yet.

Chinese SSE delta. Two local pseudo-terminal runs with a continuous loopback SSE
producer observed the cancellation notice after 0.024 and 0.017 seconds and

** Conversation journal in progress

The session layer now has a typed conversation journal over =AgentStorage=.
It appends a unique, fixed-width turn start before a caller may dispatch, then
appends the observed completion, failure with partial text, or explicitly local
cancellation. A competing stale writer cannot claim the same start key. Replay
uses storage pagination, checks event identity, order and parent linkage, and
exposes an unfinished turn without retrying it. A freshly opened journal cannot
finish that unowned turn: another process may still be its owner. An explicit
recovery protocol with authoritative ownership is still required.

This is not an exactly-once delivery or a process lease. A crash or uncertain
storage acknowledgement can leave an admitted turn without a terminal event;
there is intentionally no automatic recovery or duplicate dispatch. Replay
callbacks are provisional until the full scan succeeds. Replay now compares
committed event counts before and after scanning, and checks that the number of
observed events matches; a mismatch rejects the replay. Under the append-only
and consistent-read assumptions this detects committed additions during the
scan. It is not a cross-page transaction, process lease, cross-replica
guarantee, or protection against mutation outside the storage contract. Writes
after the final check are handled separately by the existing unique start key.
Both counts can scan the session index, and their long-history cost has not
been qualified. One local unoptimized Turso diagnostic alternated eight scans
of 1,000 unrelated 128-byte events (16 records per page): raw page iteration
in microseconds was 55251, 54576, 54729, 55596, 53358, 52832, 53326, 53227;
complete checked journal replay was 57108, 57890, 56869, 56063, 55890, 55206,
55540, 57356. The latter performs additional validation as well as two count
queries, so the difference does not isolate count cost. This is not a large
history, optimized build, real-provider or end-to-end measurement.
Record-count pagination is not a byte
budget, and long sessions still require a complete scan. The optional TUI
session path uses an asynchronous journal gateway: it persists admission
before invoking the provider, validates the stream, and persists its terminal
observation before delivering it. Cancellation or a failed turn requires
reopening; an unfinished turn remains blocked because it has no recovery
protocol. The first nonempty chunk is checkpointed before delivery; later
chunks are checkpointed in accumulated batches of at least 64 KiB. While the
stream is polled, a pending smaller batch is also attempted after one second;
backpressure, scheduling, storage latency or process failure can delay it, so
this is not a durability deadline. Each checkpoint is no larger than 128 KiB,
with a 16 MiB partial-output cap. A crash can
lose the uncheckpointed tail, and each checkpoint adds storage I/O; throughput
and long-session storage costs are not yet qualified. Replay validates ordered
checkpoint identifiers, parent links and the terminal text's prefix. A local
command-line =--session= accepts a typed session identifier in the configured
project and database. A new ID has empty history; an existing one replays its
own history. A local PTY and SSE fixture exercised two isolated sessions and
reopened the first before a subsequent request. A separate crash fixture chose
a fresh session while the prior session remained unfinished and blocked.
The storage contract also provides project-and-agent-scoped, ID-ordered
session pages. The TUI's =M-x sessions= and =M-x sessions-next= load 20 IDs per page
asynchronously, allow one outstanding query, validate ordering and cursor, and
mark the current ID. IDs above 512 bytes are omitted from that terminal view,
with the command-line listing identified as the alternative. The count bound
does not bound individual database fields or backend allocation. The
command-line listing uses this contract without requiring a
model credential, and lists sessions with events from any Marlin surface for
that scope. It is not a recency list, session readiness check, or cross-page
snapshot. =M-x session= takes a JSON-quoted ID, loads the target off the UI thread,
and swaps the gateway, replayed history and current ID only on success. Failed
or cancelled loading retains the previous session. Switching is disabled while
a model turn is active; unfinished targets remain blocked, and switching away
does not retire or retry their work. A local PTY fixture verifies both a failed
foreign-agent switch retaining the old context and a successful switch to a
previous session. The crash fixture's first in-app-switch assertion falsely
looked for a complete ID in incremental terminal output; the renderer emitted
only changed cells, so the fixture was corrected and rerun. Startup and switch
now project only the fields needed by the interface and model context. Replay
stops and returns an explicit error above 10,000 turns or 64 MiB of accounted
projection data; it never silently sends a truncated history. A switch rejected
by this budget retains the previous session. These values are provisional
engineering guards, not measured or accepted performance targets. Read-only
=M-x inspect= provides a window of at most 100 turns or 8 MiB of accounted
projection; oversized individual turns are visibly omitted without changing
storage. =M-x history-older= and =M-x history= rescan the full journal for each
page. Their separate scans are not a shared snapshot, and storage pages and
individual records are outside this projection budget. Inspection disables
model submission and retains drafts; only successful full =M-x session= loading
can restore model submission. Starting the TUI still requires model credentials.
These are logical projection
limits, not process-memory bounds: live history, storage page bodies, individual
records, journal checkpoint reconstruction and allocator overhead are separate.
The journal has no cross-page snapshot, and paging remains a full scan rather
than a storage-indexed operation. The in-memory storage implementation seeks
directly to the exclusive event cursor in its ordered map rather than scanning
all earlier projects, sessions and event pages on every request. This removes
repeated prefix traversal from that backend, but does not make a history window
a bounded-cost query; no matched end-to-end performance measurement has yet
been made for this change. History projection also evicts old items before
cloning the next selected turn, avoiding temporary overlap of those projections;
storage and replay allocations remain outside the window accounting.
Turso uses an index over project, agent and
session; opening an existing database initializes it if absent. Index creation
cost and large-project listing performance have not been measured. The PTY fixture also
verified restart and replay into a subsequent
request. A separate local PTY fixture kills the client after the loopback
provider received the request and sent a chunk, while its connection remains
open; reopening shows the first chunk and a smaller tail checkpointed after the
timer, and neither retries nor sends a new
request during the observation. Its first run falsely failed because ANSI cursor
movements split displayed words; the corrected assertion strips those sequences.
This is not proof of remote cancellation or multi-process ownership. This path
retains replayed history and up to 16 MiB of stream text in
memory; it is not a bounded-history architecture. No-live-LLM typed denial
evidence, authoritative recovery and complete partial-output retention remain pending.

** Doom-inspired Modeline and Mini Buffer

Source study pinned =.data/doom-modeline= at =d41f69ab= and
=.data/oh-my-pi= at =cfd8d04e= (both depth one, excluded from Git). Doom
Modeline declares named segments and separate left/right layouts. oh-my-pi
adds themed segment colors, width-aware priorities and cached status facts.
Marlin uses these as design references; no Elisp or TypeScript implementation
was copied. Its source of truth remains the selected Scheme/Rust UI protocol.

The selected =ui-modeline= Yuanxu Module publishes eight ordered roles:
brand, model, activity, turns, session and three gateway-state variants.
Each role declares full/compact labels, semantic tones, width thresholds and
an optional-segment retention priority. =ui= composes them with at most eight
host status contributions. The Rust projection admits at most sixteen status
items and rejects unknown roles, invalid tones, labels and bounded policy.
The Ratatui host resolves live model, session and activity facts from the
current admitted workbench and app state, maps the declared tones to terminal
colors, and retains optional segments in Scheme priority order when width is
scarce. Its former
top status heading and
default right Guide frame are removed; =M-x help= is the shortcut surface.
The initial configured-gateway notice is shown as the Modeline's idle state,
not as a synthetic transcript entry. A fish glyph marks the Marlin brand.
The right session segment preserves the distinguishing tail of long Unicode
identifiers within its allotted cells and drops the turn count first when
space is scarce. Selecting a model clears the previous route's observed
gateway status until the newly selected route has its own outcome.

The bottom Mini Buffer is the existing ChatBox in a collapsed form. With no
draft or command activity it occupies one row and can show host status that
does not belong in the Modeline. Pointer movement into that row expands the
ChatBox upward; moving above the expanded area collapses an empty ChatBox.
Typing, command editing and history search keep it expanded. A nonempty draft
stays visible after pointer exit. Termion's unsupported SGR no-button motion
is decoded from its bounded raw event; the input thread stores only the latest
pointer position, so pointer floods do not fill the eight-item key queue.
The frame scheduler samples that position and repaints on state transitions.
Some terminals may not report motion outside their window, so an external
pointer leave is not currently a guaranteed collapse event. This design does
not call Scheme on each rendered frame and adds no context-compression state.

The selected =ui-layout= Module publishes ordinary-message and =M-x= frame
specifications through the same Yuanxu publication as =ui-components= and
=ui-modeline=. Each frame declares its transcript minimum, editor sizing,
footer height, extension visibility, border and prompt. The policy also
bounds expanded ChatBox and command candidate rows. The native projection
validates these fields once per workbench; focus successors retain the frame
specifications. Ratatui maps them to cell rectangles and clips to the actual
terminal. The Rust adapter measures text, handles terminal input, owns the
viewport cache and paints cells without calling Scheme on every frame.

The focused extension now occupies the full content area instead of opening a
right-side pane. =M-x runtime= uses that same area for a view of the actual
Rust-owned =RuntimeEdgePolicyReceipt=. The receipt is projected to bounded
display fields when the gateway is installed, so repainting never formats it
again. Esc or Ctrl-C closes the view; a submitted draft also closes it.

The selected Scheme modules own Doom and oh-my-pi-inspired Modeline profiles

profile transition. Native admission preserves host status facts, focus and

** Terminal suspension and foreground ownership

The terminal host treats Ctrl-Z and external SIGTSTP as requests to suspend.
It drops and flushes the Ratatui terminal before stopping the process, so raw
mode, alternate screen, bracketed paste and mouse tracking are restored before
the shell can regain the terminal. SIGCONT reopens those guards and forces a
fresh frame from the retained App and UI snapshot. The signal observer does
not claim to stop or cancel an in-flight model request; the process-wide stop
holds its threads until continuation. A Unix PTY test observes both stop paths,
the restored termios state, a new alternate screen and an unsent draft after
each resume. It does not exercise an actual interactive shell's =fg= command
or prove checkpoint recovery across process death.

** Reference UI synthesis for Marlin Buffers (2026-11-13)

The local =.data/oh-my-pi= source separates assistant thinking display,

Marlin retains its own selected Scheme =UiFrame=/=UiWindow=/=UiBuffer= and
Minibuffer model. Conversation and =*Messages*= are different Buffer bindings
for the selected Window; M-x browsing belongs to the Minibuffer. Agent
thinking, tools and typed receipts will be semantic transcript cells, with
their presentation selected by Scheme and clipped/rendered by Rust. A tool
Ask request can temporarily bind a choice view to the Minibuffer while the
runtime holds the pending gate; the choice must resolve that exact typed gate
before the Window returns to its prior Buffer. This preserves the Emacs
interaction idea while fitting Marlin's runtime authority and stream model.

The UI Buffer is a view binding, not a second durable session or context
container. Agentic AI Lab Context and ORG define the narrative and evidence
semantics; MRR is the intended evidence and storage boundary. The current TUI
still uses the Marlin conversation journal for recovery and provider
continuation; it must not promote that journal into an independent Context
model. A transcript cell refers
to the typed event or receipt that produced it; changing Buffer, theme, fold
state, or Window does not copy or reinterpret that evidence. Consequently,
oh-my-pi and Codewhale session catalogs are
interaction references only. Marlin must not adopt their conversation storage
or reconstruction semantics.

=ui-transcript= now owns profile-specific role labels and thinking fold
defaults; =ui-layout= owns frame geometry. The selected Scheme workbench
combines both into one bounded native projection. Rust reads that projection
to paint cells and must not hard-code a second set of profile rules or call
the VM on each frame.

The previous =M-x context= command displayed only a local message-byte
admission budget. It is now =M-x context-budget= with an explicit
=context-budget= capability. No compatibility alias remains. An actual Context
Buffer must consume a scoped ORG query and its MRR-backed evidence receipt;
relabeling the existing session pager or byte counter would not provide that
projection.

Named Buffers now have one rendering route. Scheme declares the =*Processes*=
identity and title with an empty content component, and the Rust Runtime
owner atomically replaces only its bounded display content. The same route
can later display an admitted Context/ORG query result without creating a new
conversation or a one-off renderer. There is no query producer or Context
Buffer binding in this change, so it does not yet expose ORG evidence in the
TUI. The existing =ContextOrgMemoryQuery= checks common scope identities and
executes a local Org projection, but its own contract explicitly does not
authenticate the source cut or grant current use. A TUI Context Buffer needs
the admitted Lab scope and an MRR-backed evidence receipt before that result
can become a navigable view. The session pager remains a journal recovery tool
until that producer exists; copying an external session catalog into the UI
would give it the wrong authority.

session identity. The TUI skips cloning and formatting its rows when neither
changes. Runtime mutators increment the revision on managed registration,
cleanup and completion; the terminal draw path reads the last bounded view.
