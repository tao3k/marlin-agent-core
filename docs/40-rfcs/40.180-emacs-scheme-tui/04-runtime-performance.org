#+title: Marlin TUI — Runtime and performance

[[file:../40.180-emacs-scheme-tui.org][RFC entry]] · [[file:03-native-mapping.org][Mapping contract]] · [[file:05-verification.org][Verification]]

* Startup and native compilation

Separate package preparation, Scheme/C compilation, static linking, process
launch, VM initialization, first frame and first interaction. Build time is not
a startup sample. A hot second launch does not establish cold-start acceptance.
The intended default developer command remains:

#+begin_src sh
target/debug/marlin-tui crates/marlin-agent-tui/example.toml
#+end_src

The default linked debug build and release use the selected compiled Gerbil
closure. A release must work without a source package tree. Runtime expansion
of a source module is not an acceptable hidden prerequisite for a linked
binary. Scheme executes in its VM; a restricted Scheme-to-Rust backend is not
assumed to handle macros, CLOS or dynamic generic dispatch.

Darwin native compilation can avoid source expansion at launch. It does not
justify claiming zero VM startup cost. Measure the actual generated executable
and its first-copy launch. Reuse Gerbil/Yuanxu Build and Scheme Rust staging;
do not introduce a parallel loader, artifact scanner or cache hierarchy.

The earlier linked debug cohort recorded a first-M-x failure before input
because the initial Modeline missed the ten-second limit. A bounded sample with
a matching link map reached VM initialization, Yuanxu linking, POO execution and
GC. The [[file:05-verification.org][verification record]] identifies the source
cohort for that failure. Qualify the compiled closure and its bootstrap
initialization separately through the owning compiler and runtime interfaces.
Deferred activation must retain source, binding and Contract checks.

* Event scheduling

Drain events with a bound, coalesce replaceable display updates and paint at a
bounded cadence. Preserve reliable lifecycle, cancellation and approval events.
A large streaming response must not starve keyboard input, resize or Stop.
Idle redraws require observable invalidation; elapsed wall time alone is not a
reason to rebuild an unchanged Scheme projection.

Wheel coalescing preserves destination, direction and the relevant frame.
Selection navigation can process multiple events before paint, but the first
M-x arrow must be applied to the newly opened selection state. Treat input
latency, projection latency and terminal paint as distinct observations.

* Rendering and retention

Prepare changed content incrementally. Render the visible viewport, retain
bounded indexes for long transcripts and preserve anchors across folding and
resize. Avoid whole-history wrapping on each frame or native/Scheme round trips
for each terminal cell. Batch typed facts and projections at frame boundaries.

Retained Messages, transcript events, tool output and completion history need
explicit bounds or durable owners. Dropping display detail must not drop an
unacknowledged Runtime receipt. A cache hit still requires current evidence;
source identity, viewport and display revision are not interchangeable.

* Terminal ownership

Rust owns raw mode, mouse reporting, cursor, alternate screen, suspension,
foreground handoff and restoration on exit or failure. Scheme declares UI
state and intent. A native failure must not leave the terminal corrupted or
write a backtrace into conversation history.

Provider configuration, retries and uncertain remote outcomes belong to Weaver
and the Runtime. The UI can present those facts and actions; it cannot infer
that an uncertain remote request never executed or silently resend it.

* Measurement contract

Use fixed source cohorts and workloads. Report debug/release separately, with
sample counts and tails. Include normal and deep scroll, resize, folding,
first M-x navigation, event bursts and package-extension overhead. Compare the
same content, terminal size and cache state. Do not mix builds or concurrent
compilers into latency samples.

For startup, record the commit, resolved package revisions, SDK and executable
hash. Compile the test drivers before staging the measured product binaries.
Cargo can replace a product at its default path while compiling tests.
Distinguish a launch at the installed path, a new executable copy and a
second launch of the same file. Include a small native control. Record the
first process output, Rust entry, Scheme readiness, usable workbench and first
successful input separately. A first dyld message is an observation marker and
does not identify the cause of earlier elapsed time.

The subsecond first-interaction target in =MAR-TUI-R09= is a performance goal.
The ten-second workbench limit and five-second natural-exit limit remain the
failure gates. Measure plugin first use and repeated actions separately so that
deferring initialization cannot hide a delay in the first command.

The thirty two-frame Scheme test-window samples include Scheme assertions and
debug mapping. They are a diagnostic workload, not a release startup benchmark.
A failed budget remains failed evidence. Do not increase watchdogs, prewarm
business scopes or selectively repeat until a convenient sample passes.
