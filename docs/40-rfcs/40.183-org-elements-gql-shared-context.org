** 1. Motivation and Four-Engine Synergy

Traditional multi-agent systems rely on hardcoded static templates (such as
fixed =PLAN.md= or boilerplate ADR files) and isolated per-agent context
buffers. Static templates force every task — whether a 10-line bug fix, a
multi-hypothesis security inquiry, or a cross-crate protocol change — into rigid
pre-allocated shapes, while isolated agent buffers force =K= sub-agents to
re-read =N= repository tokens (=O(K * N)= token blowup).

Marlin replaces static boilerplate and full-file prompt stuffing with a
four-engine architecture inside the existing **GitOps + Artifacts + Storage**
backbone (with no parallel =OrgStore= concept):

1. **=Orgize= (=Org Elements= AST)**: Parses 100% standard Org-mode syntax
   (=org-babel=, =org-attach=, =TODO=/=SCHEDULED:=/checklists) with exact UTF-8
   byte spans =[byteStart, byteEnd)=, enabling zero-copy progressive folding and
   deterministic AST canonicalization.
2. **ISO =GQL= (=YuanxuGraph= + =GraphSyntax*=)**: Compiles composable
   =(org-elements ...)= S-expression selectors directly into governed ISO =GQL=
   graph queries across GitOps files without blind search.
3. **=ASCENT= Deductive Rule Engine (=gerbil-ascent=)**: Evaluates structural,
   intent, and causal facts **in-VM at zero LLM token cost** to drive:
   - **Dynamic Case-Specific Org Facet Synthesis** (guiding the low-cost Flash
     model to grow only the Org structure needed by the current case rather than
     shipping static boilerplate templates); and
   - **Dual-Axis Progressive Disclosure (=L0 -> L3=)** for both Org content and
     triggered rules, paired with explicit agent drill-down requests.
4. **Two-Stage Org Repair + =OrgContract= Admission**:
   - **Stage 1 (~90%, 0 LLM Tokens)**: Deterministic Org AST canonicalizer
     repairs standard mechanical syntax and structural omissions in-VM.
   - **Stage 2 (~10%, Bounded Flash Pass)**: Sends only the offending subtree
     slice and exact =OrgContract= / =ASCENT= diagnostic to Flash when semantic
     intent resolution is required.

** 3. Standard Org-mode Stream, Multimodal Attachments, and Organic Seed
:PROPERTIES:
:CUSTOM_ID: standard-org-syntax
:END:

Every session begins from a minimal organic seed ([[file:../../scheme/context-system/org-contract/templates/session-seed/seed.org][session-seed/seed.org]]) inside =tmp/<NNNN>.org=:
- **Auto-Evaluated =org-babel= Turns**: User prompts append named
  =#+NAME: <turn-id>= + =#+BEGIN_SRC llm :model ... :thinking ... :results drawer replace=
  blocks and stream directly into =#+RESULTS: <turn-id>= =:RESULTS: ... :END:=.
- **=#+BEGIN_THINKING ... #+END_THINKING= inside =:RESULTS:=**: Because Org-mode
  drawers cannot nest another =:END:= drawer inside =:RESULTS:=, reasoning traces
  use a standard Org special block (=#+BEGIN_THINKING= ... =#+END_THINKING=),
  parsed by =orgize= as an =OrgSpecialBlock= child of the =RESULTS= =OrgDrawer=.
- **Native =org-attach= Media**: Multimodal inputs and outputs use standard
  =:ATTACH:= tags, =:ID:= / =:DIR:= properties, and =[[attachment:<filename>]]=
  links stored under the enrolled GitOps owner.
- **Optional Project-Level Rule Overrides in =context.org=**: Advanced projects
  may include a declarative =:org-progressive-rules= block in =context.org= to
  adjust default disclosure thresholds (such as scratch split line watermarks or
  mandatory reviewer facets) under strict schema validation, while core rule
  execution stays in Scheme =ASCENT=.

*** 5.1 Dynamic Case-Driven Org Facet Synthesis (Replacing Static Templates)

Instead of pre-allocating static ADR or execution-plan files, =ASCENT= rules
evaluate case facts (=cross-module?=, =has-competing-hypotheses?=,
=has-attachments?=, =task-count=, =line-count=, =has-active-defeater?=) in-VM
and derive minimal **Facet Obligations**:

| Derived Facet ID | Trigger Condition in =ASCENT= | Standard Org Structure Synthesized by Flash |
|------------------+-------------------------------+---------------------------------------------|
| =inline-checklist= | Bounded single-component task with actionable steps | =TODO= heading + =[0/N]= cookie + =- [ ]= items inside current file |
| =scheduled-todo-dag= | Multi-step or multi-agent work requiring ordering | Prioritized =TODO [#A/#B]= subtrees + =SCHEDULED:= / =DEADLINE:= + =:DEPENDS_ON:= |
| =invariant-section= | Cross-module, protocol, or public ABI impact | Dedicated invariant/architecture section with =:CUSTOM_ID:= referenced via =:DEPENDS_ON:= |
| =competing-hypotheses= | Debugging or security investigation with >= 2 live causes | Hypothesis subtrees + non-droppable defeater properties + discriminator checks |
| =attach-media= | User or tool supplies/requests visual or binary artifacts | =:ATTACH:= tag + =:ID:= scope + =[[attachment:...]]= links |
| =sod-reviewer= | Governed mutation or security-sensitive component | Distinct =:AGENT_ID:= and =:REVIEWER_AGENT_ID:= properties + =:org-contract= assertion |
| =gitops-split= | =lineCount >= watermark= or completed =DONE= cluster | Zero-compaction fission into GitOps collection file with =:CONTEXT_ORIGIN_*:= lineage |

Only the compact instructions for **currently triggered facets** are disclosed
to the Flash model, saving thousands of system-prompt tokens on every turn.

*** 5.2 Four-Level Progressive Reading (=L0 -> L3=) and Agent Drill-Down

| Level | Disclosed Org AST Slice | =ASCENT= Derivation Rule |
|-------+-------------------------+--------------------------|
| **=L0= Skeleton** | Headline stars, =TODO=/=DONE=, priority, title, =[done/total]= cookie, =:TAGS:=, and =:ID:= only; all drawers, checklists, =#+BEGIN_THINKING=, and bodies folded | Default global map for unrelated or settled =DONE= sections without defeaters |
| **=L1= Contract & Checklist** | =L0= + =:PROPERTIES:= + =SCHEDULED:/DEADLINE:= + unchecked =- [ ]= items | Ready =TODO= candidates and 1-hop =DEPENDS_ON= task neighbors |
| **=L2= Synthesis Body** | =L1= + =#+RESULTS:= conclusion body and =[[attachment:...]]= links (**=#+BEGIN_THINKING= stays folded**) | Active task target and settled =DEPENDS_ON= invariant/architecture sections |
| **=L3= Full Evidence & Thinking** | Complete raw subtree including =#+BEGIN_THINKING= traces, =#+BEGIN_SRC= prompts, and failure logs | Triggered **only** when =ASCENT= detects an active defeater, failed assertion/test, or an explicit **Agent Drill-Down Request** (=(expand-org-element <id> L2|L3)=) |

** 6. Three-Tier Model Division of Labor and Two-Stage Org Repair
:PROPERTIES:
:CUSTOM_ID: two-stage-repair
:END:

1. **Three-Tier Model Collaboration**:
   - **Tier 1 Architect (High-tier Reasoning)**: Synthesizes core invariants,
     root-cause reasoning, and multi-step =TODO= DAGs once inside =#+RESULTS:=.
   - **Tier 2 Builder (Mid-tier Coding)**: Reads =L2= slices of its ready =TODO=
     and =:DEPENDS_ON:= anchors (+ =L0= project map, with on-demand drill-down),
     executes code/tests, updates checklists, and marks =DONE=.
   - **Tier 3 Curator (Low-tier Flash)**: Materializes =ASCENT=-triggered Org
     facets, populates deterministic =:PROPERTIES:=, executes =gitops-split=,
     and handles Stage 2 semantic Org repairs.
2. **Two-Stage Org Repair Pipeline**:
   - **Stage 1 — Deterministic Org AST Auto-Repair (~90%, 0 Tokens)**:
     Before invoking any model for syntax repair, pure Scheme AST normalization
     fixes mechanical defects in-place:
     1. Converts accidental nested =:THINKING: ... :END:= drawers inside
        =:RESULTS:= into valid =#+BEGIN_THINKING ... #+END_THINKING= special blocks;
     2. Closes unclosed =:PROPERTIES:=, =:RESULTS:=, =#+BEGIN_SRC=, or
        =#+BEGIN_THINKING= blocks at section/EOF boundaries;
     3. Normalizes malformed headline spacing, tag colons (=:ATTACH= -> =:ATTACH:=),
        and checkbox tokens (=-[x]= / =- [x]= -> =- [X]=);
     4. Recomputes stale =[done/total]= and =[pct%]= statistics cookies from
        actual child =OrgListItem= states;
     5. Synthesizes missing deterministic root/origin properties
        (=:GITOPS_PROJECT:=, =:CONTEXT_ORIGIN_*:=).
   - **Stage 2 — Diagnostic-Guided Flash Semantic Repair (~10%)**:
     If =OrgContract= or =ASCENT= still reports a semantic violation after
     Stage 1 (such as a missing required =:DEPENDS_ON:= target or unresolved
     contract assertion), the engine packages **only** the failing subtree slice
     and structured diagnostic receipt into a bounded Flash repair request, then
     re-runs Stage 1 + =OrgContract= admission (failing closed if still invalid).

*** 7.1 Eliminating Production Multi-Agent Failure Modes by Construction

Complex real-world coding-agent deployments (evidenced across production issue
trackers in =anthropics/claude-code= — e.g., =#32099=, =#23821=, =#16209=,
=#33651=, =#29751= — and =openai/codex= — e.g., =#23095=, =#33144=, =#38478=,
=#16358=, =#32035=, =#42693=, =#45102=, =#45401= — as well as 2026 governed
multi-agent memory literature such as *Governed Shared Memory*
(=arXiv:2606.24535=), *Governed Memory* (=arXiv:2603.17787=), and *Experience
Orchestrator* (=arXiv:2608.11207=)) consistently fail along four structural
fault lines when agents are built on flat chat buffers and lossy compaction:

1. **Compaction data loss & cross-provider replay failure**: Lossy =/compact=
   drops subagent results or breaks rollout replay across model providers.
   Marlin eliminates lossy compaction via shared Org-as-Context, zero-token
   =L0..L3= progressive folding, and content-addressed =FunFlow= /
   =durable-journal= checkpoints.
2. **Worktree drift & unguarded scope leakage**: Naming a Git worktree inside
   a text prompt does not enforce workspace isolation. Marlin encodes worktree
   custody, write spans, and visibility inside C4-derived POO Task objects
   gated by =Governance= (=ContextScope=, 6-tuple =RestrictionEnvelope= meet,
   and one-shot =AuthorizedEffectToken=).
3. **Ghost status, thread collision & UI/backend split-brain**: Volatile UI
   panels drift out of sync with background workers on restart or parallel
   dispatch. Marlin makes Plan-A =index.org= + =durable-journal= the single
   authoritative truth and computes TUI tabs as a pure functional projection.
4. **Fleet-memory contamination**: Unauthorized leakage, stale propagation,
   contradiction persistence, and provenance collapse are prevented by
   generation-bound =source-cut= checks, 5-level =TrustLattice= non-self-review
   promotion, non-droppable defeater cores, and =:CONTEXT_ORIGIN_*:= lineage.

*** 7.2 Doom-Emacs-Style Declarative Interface Architecture

Following Doom Emacs's strict separation between stable engine mechanisms and
thin declarative configuration (aligned with =scheme/init.ss= =(module +flag)=
selection), **declarativity is the core contract of the Interface layer**:

1. **Core Engine Plane (Lab + Yuanxu)**: Implements pure functional mechanisms
   and MOP =.defgeneric= dispatch protocols (=Org Elements -> GQL=, =ASCENT=,
   =FunFlow= DAG/CAS, =Governance= isolation, =durable-journal=, =policy-clock=,
   =agenda=, recovery, AST repair). Engine internals never hardcode repository
   paths, tab presentation, or archive UX.
2. **Declarative Interface Plane (=interface.ss= + Hygienic Macros + POO)**:
   Exposes compile-time hygienic Scheme macros (e.g., =define-repo!=,
   =define-worktree!=, =define-durable-task!=, =define-orchestrator-strategy!=)
   and composable POO prototypes with =+feature= flags (=+plan-a-index=,
   =+funflow-dag=, =+cas-resume=, =+durable-agenda=, =+auto-archive=,
   =+progressive-l0-l3=, =+two-stage-repair=, =+worktrunk=). Macros expand
   statically into validated POO values with zero runtime =eval=.
3. **Thin User / Repository Config Plane**: Both Scheme repository declarations
   and inert Org configuration blocks (such as =:org-progressive-rules=) parse
   and validate onto the **exact same POO =Type.= policy contracts**, inherited
   uniformly via C4 linearization. Changing one slot at the declarative
   interface keeps =GQL=, =ASCENT=, =FunFlow=, =Governance=, =Durable=
   scheduling, Plan-A =index.org= sync, and TUI tab visibility in lockstep.

*** 7.3 =gerbil-poo= C4 Linearization (=A -> B -> C -> D=): Objectified Tasks, Shared Context, and Override/Extension

Rather than copying configuration or re-parsing Org files per agent, every
repository, worktree, task, sub-task, and orchestration strategy is a
first-class **POO prototype object** composed via **`gerbil-poo`'s C4
linearization algorithm** (deterministic precedence linearization with full
Override and =super= Extension support across multi-prototype mixins):

- **=A= (=Repo.= — Root Prototype)**: One Git repository forms the first root
  node =A= of the C4 derivation chain, owning the shared parsed
  =OrgElementGraph= reference, authoritative =index.org=, =topology.org=,
  =ArtifactCatalog=, organization/SoD roles, default =DurableTaskPolicy.=, and
  default =OrchestratorStrategy.=.
- **=B= (=Worktree.= = =(:: @ A)=)**: A GitOps worktree derives directly from
  =A=, inheriting the shared context graph, =index.org= authority, and defaults
  while overriding only =worktree=, =branch=, =source-cut=, local sandbox/envrc
  bindings, and worktree write grants.
- **=C= (=Task.= = =(:: @ B OrgTaskBase.)=)**: Every managed task is a POO
  object parsed symmetrically from (and projected back to) its Plan-A Org
  document. It inherits =A='s shared context object and =B='s worktree bounds
  with zero copy, adding its =task-id=, =ContextScope=, =RestrictionEnvelope=,
  =context-selectors=, and child =FunFlow= DAG specification.
- **=D= (=SubTask.= / =Extension.= = =(:: @ C Mixin...)=)**: Sub-tasks and
  policy refinements derive from =C= (and arbitrary mixins such as
  =StrictSodReviewMixin.= or =IsolatedSandboxMixin.=) under C4 linearization:
  - **Override**: Specialize =model-tier= (=architect= / =builder= / =flash=),
    =needs=, or =disclosure-depth= locally without mutating =C=.
  - **Extension (=super=)**: Layer additional checks onto =.verify=,
    =.admit-node=, or =.archive-guard= cleanly atop inherited behavior.
  - **Shared Object-Level Context + Governance Isolation**: All sibling objects
    =D1, D2, D3= share one in-VM parsed =OrgElementGraph= reference while each
    object carries its own =ContextScope= and 6-tuple =RestrictionEnvelope=
    (enforced via lower-semilattice =meet=), guaranteeing zero cross-scope
    leakage and disjoint =:ID:= write leases.

*** 7.4 Tweag-Inspired =FunFlow= DAG: Static Inspection, CAS Resumability, and Epoch-Bounded Replanning

Inspired by Tweag's Haskell =FunFlow= (Arrow static inspectability,
content-addressed store caching, and crash resumability) and owned directly by
=tao3k/agentic-ai-lab/modules/funflow/= (=durable-dag.ss=, =dependency-graph=,
=scc=, =job-graph=, =after-start= finalizers, =flow-compose=, =strategy=),
complex tasks execute as **isomorphic Org AST <-> FunFlow POO DAGs**:

1. **1-to-1 Org <-> FunFlow Isomorphism**:
   - Each child headline with =:ID:= and =:DEPENDS_ON:= projects to a POO
     =FunFlow= task node (=needs:=) whose late-bound =.run= slot automatically
     specializes to its C4-derived =Worktree= =B=.
   - Cleanup/rollback sub-headlines project to =FunFlow= exceptional-exit
     =after-start= finalizers.
2. **Arrow-Style Static Pre-Execution Analysis (0 LLM Tokens)**:
   - Before spending any model token, =FunFlow= runs Tarjan =scc= cycle
     detection, verifies =:DEPENDS_ON:= closure and finalizer admissibility,
     and validates every node's =ContextScope=, =RestrictionEnvelope=, and
     =UseGrant= statically (failing closed on violation).
3. **Content-Addressed Caching & Crash Resumability (CAS + =durable-journal=)**:
   - Every DAG node carries a deterministic content fingerprint
     =sha256(source-cut, input-org-slice-digest, node-contract-digest, policy-digest)=
     recorded in =durable-journal= and =ArtifactCatalog=.
   - Pure deterministic steps (AST repair, GQL query, ASCENT solve, build/test
     gates) hit CAS and skip at zero cost; verified LLM steps whose outputs
     passed =OrgContract= and were frozen into =#+RESULTS:= + journal are
     likewise skipped on crash recovery or re-run, saving 100% of prior LLM
     tokens.
4. **Parallel Frontier Waves with Disjoint Org Leases**:
   - All =indegree == 0= =TODO= nodes form a ready frontier wave; nodes whose
     Org =:ID:= byte spans are disjoint (admitted by =funs-subtree-mediation=
     and Rust =OrgGovernanceLedger=) dispatch concurrently without mutual
     interruption.
5. **Epoch-Bounded Dynamic Replanning**:
   - Within generation =g=, the =FunFlow= DAG is 100% statically verified.
   - When an agent discovers an unforeseen blocker and writes a new sub-heading
     into the shared Org document (advancing to generation =g+1=), =ASCENT= and
     =FunFlow= re-project and re-verify the DAG in milliseconds: unchanged
     completed nodes remain satisfied from CAS/journal while only affected
     downstream waves re-sequence.

*** 7.5 Objectified =OrchestratorStrategy.=, Plan-A =index.org=, and Atomic Auto-Archive

Orchestration policies themselves are C4-derivable POO prototypes exposed at
the Declarative Interface plane:
- =OrchestratorStrategy.= (base MOP hooks for frontier selection, admission,
  recovery, and archive guards) -> =ParallelFrontierStrategy.= ->
  =TieredModelStrategy.= (routing nodes via =ASCENT= facets and =L0..L3=
  slices) -> =DurableGovernedStrategy.= (wrapping node transitions in Lab's
  =Durable= =durable-journal=, =policy-clock=, =agenda=, and
  =AuthorizedEffectToken=).

Storage and task indexing follow **Plan A** (no hardcoded flat =tasks/= folder):
- **=index.org= (Compact Authoritative Index)**: Stores every task's Org
  lifecycle metadata (=TODO=/=IN_PROGRESS=/=BLOCKED=/=REVIEW=/=DONE=,
  =SCHEDULED:=, =DEADLINE:=, =CLOSED:=, =[done/total]=, =:ARCHIVE:=,
  =:WORKTREE:=, and =[[id:...]]= / =[[file:...]]= links) with zero verbose
  bodies or thinking traces.
- **Independent Task Org Documents**: Owned declaratively via
  =ArtifactCatalog=, preventing multi-agent file contention and verified
  against =durable-journal= digests on restart.
- **Organic Scratch Promotion**: Default =scratch-promotion: 'on-plan= keeps
  trivial one-shot questions out of persistent tabs until promoted by the user
  or =ASCENT=.
- **Four Zero-Token =ASCENT= Orchestration Predicates** (evaluated over Org
  AST + =FunFlow= closure + =durable-journal=):
  - =ready_to_schedule(task_id, node_id, model_tier)=
  - =needs_recovery(task_id, attempt_id)=
  - =ready_to_auto_archive(task_id)=: Top-level Scope Root is =DONE=, **every**
    reachable =FunFlow= DAG node and child TODO is =DONE=, **every** checklist
    item is =[X]=, no finalizer or review gate is pending, and
    =durable-journal= confirms **zero in-flight attempts or uncommitted side
    effects**.
  - =tab_visible(task_id)=: Task is non-archived (active) OR present in
    transient =ui-peek-set=.
- **Atomic Auto-Archive Transaction**: When =ready_to_auto_archive(task_id)=
  holds, the single-owner Durable Orchestrator atomically: (1) writes
  =CLOSED: [timestamp]= and =:ARCHIVE:= to the Task Org via parser-verified
  update; (2) synchronizes =index.org=; (3) commits an idempotent archive
  receipt to =durable-journal=; and (4) publishes a new immutable
  =WorkbenchTabProjection=.

*** 7.6 Task-as-Tab Workbench Projection and MOP =.defgeneric= Protocol Surface

TUI tabs are a **pure functional projection** of
=(OrchestratorSnapshot, UiPeekSet)= — TUI memory never owns task lifecycle or
archive state:
- **Left Pinned Group (=Index=)**: Permanently visible, non-closable tab over
  =index.org= (filterable by worktree, status, schedule, or Active/Archived).
- **Right Dynamic Group (=Active Task Tabs=)**: One Centaur Tab per active
  Org Task (replacing legacy session-centric =Chat / Messages / Sessions=).
