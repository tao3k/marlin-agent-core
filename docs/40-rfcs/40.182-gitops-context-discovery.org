** Repository binding

Lab's [[https://github.com/tao3k/agentic-ai-lab/blob/731f6dfb0466aa47e51b04040db579e5e751ba47/modules/gitops/types.ss][GitOpsSourceCut]]
carries project, worktree, path, Git HEAD and source text. Its Worktree
prototype and dependency reader consume a selected Project, Worktree and
source cut. Marlin GitOps supplies the additional local topology and remote
route, then passes the corresponding observation to Lab. A Lab Project can
relate multiple repos. A ref identifies a branch and a Worktree identifies a
checkout, including a detached HEAD.

| Input | Binding decision |
|-------+------------------|
| Local repository | Enroll once under an explicit GitOps operation. The durable owner records a fresh repository instance key bound to the canonical Git common directory and observed directory identity. All linked Worktrees use that binding. Resolve a moved repository through explicit rebinding. A replacement at the same path or a conflicting registration is unavailable until rebound. |
| Worktree and ref | Resolve Git top-level, per-Worktree Git directory, common directory, full symbolic ref when present, and exact commit OID. Retain distinct HEAD, index, working and selected untracked observations as needed. A changed ref or selected input invalidates the corresponding cut. |
| Remote choice | Select an explicitly configured source remote, otherwise =origin=, otherwise the sole eligible network remote. Multiple eligible remotes without a choice are ambiguous. A selected remote must resolve to one eligible fetch route or an explicit local route. Distinct fetch routes require a choice. An invalid selection is a binding error. A local route or a repo without remotes uses =repos/_local/<instance>=. |
| Route | Normalize the fetch URL to percent-encoded path segments under =repos/<host>/<namespace...>/<repo>=. Fold the host, strip one terminal =.git=, discard userinfo and reject query, fragment, encoded separators and dot segments. Encode uppercase and reserved characters in path segments so case-sensitive identities survive on case-folding filesystems. Standard HTTPS and SSH routes to the same host/path agree. Retain nondefault ports in the authority component. A URL change is a route update with owner evidence. |
| Related repositories | The declared Lab Project and admitted relations choose related repos. Two clones of a URL share its route and retain separate instance keys and observations. A fork has its own URL route. |
| Storage mode | Ordinary mode uses =~/marlin-ai/index.db= with Repo routes below =~/marlin-ai/repos/=. =MARLIN_AGENT_CORE_DEV=1= selects the main Worktree's =.data/marlin= for that repository's development data and index. A bare repository uses =<git-common-dir>/marlin= in DEV. DEV includes only explicitly enrolled source roots and uses a separate index scope. Startup outside Git or before enrollment returns an unavailable view. |

Read the common-directory and Worktree facts through
[[https://git-scm.com/docs/git-rev-parse][Git plumbing]] and the existing
Marlin GitOps native boundary. Scheme =config.ss= will select mode, eligible
source remotes, policy and owner bindings. Rust will resolve canonical paths,
read the registered owner and observe Git through bounded host operations.
Terminal startup can read the binding. Enrollment and rebinding are explicit
owner operations.

The producer's durable owner records are the rebuild roots. In home mode each
Repo route has a separate owner record per enrolled local instance. A route
change updates discovery after the owner records the verified binding. The
owner keeps custody at its recorded location until an explicit move completes.
In DEV the enrolled primary Worktree root or bare root owns the records.
Traversal of those owner roots rebuilds the selected index scope. Locators
refer to the owner records and payload by identity.

In the ordinary single-repository path, =marlin-tui <config.toml>
--enroll-context= writes =owner.json= under the selected Repo route and
publishes a relative =marlin-owner-ref= in the Git common directory. Startup
validates the owner record against the observed common directory before
issuing a read permit. The terminal validates the same enrollment again
before passing the read result to Lab. The Git reference locates the owner
record directly, including when the configured remote changes.

** Top-level locator index

The first backend is the Turso driver already selected by Marlin. The
[[https://github.com/tao3k/mrr-data/blob/daa6487820f798f0583713de8d03110aeac5d1fd/crates/mrr-data-backend/src/lib.rs][exact MRR Data pin]]
exports =turso_driver= explicitly for hosts that own their schema and
transactions. Marlin already uses cached prepared statements and indexes in
[[file:../../crates/marlin-agent-storage/src/turso_storage.rs][its storage adapter]].
Use that driver and a Marlin-owned locator schema. Locator indexes are
derived, so one transaction advances affected source membership and its owner
change cursor together. Crash recovery consumes owner records after that
cursor. A cursor gap marks that scope incomplete until reconciled.

The Turso projection persists each owner's applied cursor and observed
frontier. A contiguous delta changes only the named cut. An owner inventory
can replace that owner's projection after reaching the recorded frontier.
Replacing a projection leaves other owners' rows untouched. Retirement checks
the indexed tip and records its reason. Git and the producer retain physical
custody of the original object.

The lookup key starts with storage scope, repo instance, and ref cut or
detached commit. A row identifies a source, generation, owning locator and
coverage. Indexes over repo route and declared relation endpoints support
bounded candidate lookup. A locator can reference one Git commit and path or
a retained content object with its digest. Org bodies and artifact payloads
live with the source owner. A warm lookup seeks the scoped rows and opens
only admitted sources; owner writes invalidate changed cuts and declared
dependents. First build, cursor gaps and explicit repair use replay of the
affected owners.

Lab's [[https://github.com/tao3k/agentic-ai-lab/blob/731f6dfb0466aa47e51b04040db579e5e751ba47/modules/query/orgize-source.ss][incremental Org query]]
reuses selected open-headline rows after replay verifies the old source. It
still re-parses source reads for that bounded profile. Reuse it for that
profile and measure its cost independently from locator deltas.

| Layer | Source finding and selected use |
|-------+---------------------------------|
| MRR Data pinned =mrr-data-backend= | Reuse =turso_driver= for the locator projection. Marlin owns visibility, key layout, transactions and coverage. |
| Lab Context and GQL | Use the selected Worktree Feature, source registration, per-source query and Task publication for the first Context path. Filter candidate visibility before source I/O and qualify every returned anchor. |
| MRR query admission | [[https://github.com/tao3k/meta-relational-reasoning/blob/d5bc42942b53b0c57c4ac30b006f53ae87d81ac1/crates/mrr-property-source/src/source_query.rs][MRR source query]] binds original GQL, catalog and snapshot and admits typed results. Use this contract when qualifying graph queries over Lab-admitted relations. |
| MRR Data physical graph execution | The inspected development head =55285d510bd655fd546d73e07400c642bdf534e4= has a [[https://github.com/tao3k/mrr-data/blob/55285d510bd655fd546d73e07400c642bdf534e4/crates/mrr-data-poo-flow/src/property_source.rs][DataFusion property-source worker]] over verified snapshots. An index row grants neither access nor result validity. Lab checks display
authority before dereferencing the source and rechecks currentness before
publishing the result. Across repositories the same locator mechanism supplies
candidates through admitted project relations. The first Worktree integration
selects Repo modules through the active Lab Project. Each additional Repo
requires an admitted source binding, Module selection and current grant.

** Ref retirement and resource ownership

GitOps retires the exact observed ref tip. For an ordinary merge, require Git
ancestry into the selected target tip. For squash or rebase, require an
admitted merge receipt binding source repo, source ref and tip, target repo
and ref, and result commit present on the observed target. Deleting a ref
retires membership with reason =deleted=. It supplies no merge evidence.
If a branch advanced after the accepted merge, the new cut remains a separate
active member. Stale, conflicting or unavailable merge observations leave
current membership unchanged.

Lab's existing
[[https://github.com/tao3k/agentic-ai-lab/blob/731f6dfb0466aa47e51b04040db579e5e751ba47/modules/ai-agentic-context/features/memory/durable/artifact-object.ss][durable Artifact]]
and [[https://github.com/tao3k/agentic-ai-lab/blob/731f6dfb0466aa47e51b04040db579e5e751ba47/modules/ai-agentic-context/features/memory/durable/artifact-policy.ss][manifest policy]]
carry producer, owner, retention, visibility and lifecycle. The transition
returns a policy value. The effect owner proves which bytes are held and
which physical effect completed.

| Source | Owner action and physical cleanup |
|--------+-----------------------------------|
| Committed Org or other Git-backed source | GitOps claims one private retention ref per retained commit in its owning repo before publishing a durable historical locator. Verify the commit and path and update the ref with the expected old value. Releasing the last live hold and retained-policy reference permits dropping that owned ref. Git's normal reachability/GC policy handles object reclamation. |
| Selected dirty or untracked bytes, generated outputs | The producer registers and owns one immutable captured object in its declared local store. Reuse the pinned MRR Data =FilesystemContentStore= for bounded verified put/get where that store is selected. =ContentStore= exposes no deletion method. Physical cleanup requires a producer-owned deletion capability qualified against the same custody fence. Until then keep the bytes, report pending reclamation and retain the evidence. |
| Top-level index | Rebuildable locator rows and cursors follow owner receipts. Withdraw current membership on ref retirement. Remove stale locators or evict derived cache entries without counting that as deletion of original bytes. |

An owner acquires a hold before publishing a live reference, including when a
second Repo links to its source. Unknown publication or incomplete reference
coverage retains that hold until reconciliation. Cleanup runs under the same
owner fence as hold acquisition and checks retention policy, generation, live
holds and ownership again at commit. Keep durable sources by default. A
configured expiry can nominate Marlin-owned resources for explicit
maintenance. Missing or ambiguous provider custody is reported as unavailable.
These operations leave user branches and Worktree files under their existing
Git owners. See [[https://git-scm.com/docs/git-update-ref][Git ref updates]]
and [[https://git-scm.com/docs/git-gc][Git reachability and GC]].

The Git custody service keeps one private commit reference per retained tip.
A separate reference points to a blob containing the hold ledger. The blob
has no Git reachability edge to the original Org. A single Git ref
transaction compares the previous ledger and pin before changing either.
The index checks the selected locator before acquiring a hold and again
before handing out a historical receipt. If the locator changed during
acquisition, the holder stays in the producer ledger for reconciliation.
Disposal after branch deletion verifies the branch's absence in the same
ref transaction. The policy owner still provides expiry and coverage.

** Git and Jujutsu library boundary

Worktrunk supplies Git worktree operations. A Context read against an
ordinary Git checkout must preserve the repository's existing refs and
object lifetimes. In a scratch Git repository, =jj-lib= 0.47.1
=GitBackend::init_external= created =git_target= and an =extra= metadata
store. Its first =read_commit= of an unimported commit created a

** First integrated read

Start with an already checked-out Worktree. It gives the normal application
entry a physical Git root even when no Worktrunk create command ran in this
process. GitOps binds that observed checkout to the enrolled repository
and resolves its symbolic ref or detached commit. A remote URL routes
discovery while the Git common directory and independent Worktree facts
bind the local instance. Reuse GitOps discovery and receipt types where
they carry the required evidence. A provider command receipt establishes
the selected checkout path. Re-observe the resulting Git facts before
using it as a Context source.

The Marlin Context System supplies an owner-bound Worktree dependency and
a bounded source admission call to Lab. Lab owns the public selection,
Contract evaluation, grants and Task lineage. Marlin owns the locators and
the physical Git reader. For the first read, select the declared
=index.org= and =topology.org= in the observed checkout at a committed
cut. Check authorization before opening the selected objects and again
before admission. Register the verified Org cuts and let the Lab Worktree
resolver produce the view. On a rejected, revoked or superseded read,
leave prior immutable cache entries intact and withhold the current view.
Bring cross-repository discovery and locator indexing in after this
single-owner path has independent evidence.

Worktrunk create and switch then produce the same observation input as
launch into an existing checkout. Bind the driver's actual receipt rather
than the request's placeholder path. Selecting a different Worktree
advances the restore request identity and retires the previous current
view. A failed operation preserves the earlier binding. Git identity
and the admitted Org source cut govern restart.

* Qualification plan

Performance claims require an admitted-result oracle and source-bound
measurements. Compare the same Query, source generations, visibility and
result bounds on cold, warm, incremental and rebuild runs. Record first
frame separately from the first admitted view. Collect elapsed time, bytes
read and written, number of sources opened, number of locator rows changed
and peak RSS. Vary unrelated repository/source count independently of the
number of matches and changed cuts. Require zero unrelated source opens in
warm and one-cut cases. Set latency and storage budgets from the measured
baseline before qualifying the Turso design for production.
