* Scope

This is a diagnostic observation, not an accepted startup benchmark. Other
sessions changed the shared worktree during =just tui-aot-build=, so the output
cannot be assigned an exact source tree. The completed arm64 Mach-O binary is
identified by SHA-256 =707fd328722349910919fc59eafa6c4bcd90e185b79d1db198518ab5a28df98e=
and measures 104,120,192 bytes. The build finished in 7m 58s. Its embedded
ad hoc linker signature covers 25,223 page hashes. The staged AOT manifest
contains 896 modules; this count does not say which modules execute at startup.

Both Marlin early-exit runs reported approximately zero user and system CPU
time from =/usr/bin/time -p=. They exited before configuration and Scheme VM
initialization. The small executable control also had a first-copy delay;
therefore the observations do not attribute the full Marlin delay to its size,
code signature, dyld, storage, or any single OS mechanism. =strip -x= reduced a
copy by only 16 bytes and is not a viable size optimization for this binary.
An attempted =DYLD_PRINT_STATISTICS= launch produced no dyld counters on this
host while the fresh-copy early exit still took 3.57 s; it is not an
attribution trace.

The existing source-free linked Release PTY test passed once with the
workbench visible after 208.250833 ms in a warm run. The first run inside the
paired PTY benchmark reported an internal first frame at 199.18075 ms after
application entry. Both attempts to complete that benchmark failed when its
second =openpty= returned =ENXIO=, including one unsandboxed attempt. No cold
and warm PTY pair, percentile, or release startup acceptance is claimed.
The ignored Rust =launch= diagnostic is now part of =tui-performance-bench=;
its one observed run passed and identifies the same Release binary hash.

* ABI and first-copy follow-up

The linked UI already exports Scheme procedures with =c-define= and calls
them through the SDK's rooted object ABI. Replacing the spelling with
=c-lambda= does not remove the observed wait before the application's
terminal check. It could change interaction cost only if a measured
dispatch, projection, rooting, or decoding path is reduced. The current
Rust hot-path benchmark starts after the Scheme snapshot is projected and
therefore cannot establish the cost of this native boundary.

The Release binary has a =com.apple.provenance= extended attribute. Four
fresh-copy early-exit launches took 2.11, 2.03, 1.91, and 1.90 seconds,
respectively. An attempted attribute removal reported success but left the
attribute present; =/bin/cp -X= also left it present. This is not a valid
attribute A/B comparison and gives no causal attribution to provenance.
The binary dynamically links Nix OpenSSL, SQLite, and libiconv libraries in
addition to macOS libraries; no isolated dynamic-link comparison has been
performed.

The native workbench decoder now retains the top-level field name on failure;
the extra allocation occurs only when constructing an error. Its focused Rust
projection test passed. =just tui-aot-debug= restaged Scheme and rebuilt the
linked Debug binary; the source-free paired PTY startup test passed.

After that gate rejection, a separate bounded =script= PTY diagnostic launched
this exact binary with the example configuration and an absent Gerbil install.
Its trace reached UI session projection at 349.221 ms, view admission,
tool-catalog binding, and terminal alternate-screen entry without the earlier

it captured no complete workbench frame. This narrows the earlier failure to
an artifact/staging-specific event but does not establish its cause or satisfy
the maintained source-matched startup gate.

A further direct launch of the same binary in an allocated PTY rendered the
80-column workbench with the Marlin modeline and minibuffer. =Ctrl-Q= exited
normally and restored the terminal. The internal trace reported first frame
at 584.366 ms in this one diagnostic launch. This establishes that the second
size-profile artifact can reach a visible frame without a Gerbil install;
the sample is not a cold-start distribution and does not replace the maintained
source-matched pair, which the intervening staging change still prevents.
