* Codex lifecycle and telemetry research (2026-11-13)

These are public reports and source references, not claims about every Codex
version or proof that a proposed mitigation has shipped. They guide macOS
qualification of Marlin's own implementation. The linked source pages follow
=main= and are not pinned to an exact commit; verify the revision before
using them as release evidence.

- [[https://github.com/openai/codex/issues/15379][openai/codex#15379]] reports macOS children surviving normal parent exit and
  warns about aborting waiter tasks before reaping. Marlin must keep cleanup
  tracked until OS exit and distinguish task cancellation from resource drain.
- [[https://github.com/openai/codex/issues/19958][openai/codex#19958]] reports an interrupted macOS status process spinning
  with revoked stdio. Test closed stdin/stdout and verify actual OS state, not
  just a terminal completion event.
- [[https://github.com/openai/codex/issues/60298][openai/codex#60298]] reports concurrent client starts overwriting a process
  handle. Test concurrent admission, ownership registration and close/start
  races; a PID or latest handle alone is not sufficient authority.
- [[https://github.com/openai/codex/issues/37244][openai/codex#37244]] reports macOS zombie accumulation associated with a
  sampling path. Monitoring must itself be bounded and its subprocesses reaped.
- [[https://github.com/openai/codex/issues/42837][openai/codex#42837]] reports an OpenTelemetry event-name mismatch. Require
  tests on the exported semantic name and attributes, not just local tracing.
- A search snippet described an independent stdio watchdog, but the fetched
  [[https://github.com/openai/codex/blob/main/codex-rs/app-server-transport/src/transport/stdio.rs][stdio transport source]] did not contain it. Treat this as unverified and
  do not claim that this mechanism exists in the inspected source.
- Codex's [[https://github.com/openai/codex/blob/main/codex-rs/otel/README.md][telemetry package documentation]] describes an in-memory exporter
  for tests and explicit shutdown to flush metrics. That separation and an
  exporter-level test are useful design references for Marlin.

* Namespace and ownership

The =marlin_agent_runtime::process= module owns process lifecycle. The existing
=marlin-agent-telemetry= crate owns local sampling, host watchdog evidence,
OpenTelemetry trace export and provider shutdown. It implements the sampling
port in =marlin-agent-protocol=. Runtime consumes that port with its own managed
PID inventory. TUI wires the ports and sends a read-only budget status through
the existing UI open ABI to the selected Gerbil Module.
The bounded process executor observes its monotonic command deadline with
=ProcessCommandWatchdog=. The owned process handle binds the deadline and
compares session, operation, and generation before starting cleanup. A separate
health observer samples the host heartbeat and process stdout progress. The
TUI workspace path uses a two-second heartbeat threshold and three-second
stdout silence threshold. It publishes advisory notices through a bounded
queue. The existing ten-second command deadline still governs workspace reads.
Advisory observations never initiate cleanup, including when their identity
matches the current resource. Fresh heartbeat or stdout evidence rearms its
own condition. A missed heartbeat says the host did not report progress within
the threshold. It provides no proof of host death.

[[https://github.com/anthropics/claude-code/issues/88071][Claude Code #88071]] reports task termination after the launching session
became idle. [[https://github.com/anthropics/claude-code/issues/73332][Claude Code #73332]] reports mid-work reaping with orphan-watchdog
evidence on related jobs. [[https://github.com/openai/codex/issues/33372][Codex #33372]] reports an interrupted task remaining in a
thinking state without a useful distinction between waiting and orphaning.
These reports motivate separate host and task observations. Marlin tests the
current and stale identities against live OS processes and keeps explicit quit
and command deadline reclamation in the Runtime reaper.

For exported telemetry, follow OpenTelemetry's distinct [[https://opentelemetry.io/docs/concepts/resources/][resource]],
[[https://opentelemetry.io/docs/concepts/instrumentation-scope/][instrumentation scope]] and metric attribute concepts. Use stable
=marlin.runtime.process.*= and =marlin.runtime.resource.*= names for proposed
instruments; process/session IDs belong in controlled traces or logs, not
unbounded metric dimensions. Do not export command lines, paths, credentials or
user content by default. These names and policies require review and exporter
integration tests before they become a supported contract.

* Independent failure detection and admission

[[https://ecommons.cornell.edu/entities/publication/7948ff49-7263-49f8-a29b-d062e7cbb240][Chandra and Toueg's failure-detector model]]
separates suspicion from correctness properties. Marlin uses separate
monotonic clocks for terminal and Tokio progress. The macOS sidecar uses
[[https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/kqueue.2.html][Darwin EVFILT_PROC with NOTE_EXIT]]
to establish exit independently. The sidecar has no managed process handles.
[[https://web.eecs.umich.edu/~mosharaf/Readings/Leases.pdf][Gray and Cheriton's leases]]
motivate naming the holder and expiry conditions explicitly. Here the
Runtime reservation is tied to cleanup evidence and pipe ownership. Transferring
cleanup after host death would require an independently established owner with
authority over the old generation before the host dies.

[[https://github.com/openai/codex/issues/56117][Codex #56117]] reports a stall
during memory pressure and a failed relaunch by the reporter's own watchdog.
[[https://github.com/openai/codex/issues/24551][Codex #24551]] reports possible
surviving helpers after app exit. These are reported observations with incomplete
causal attribution.

Local admission uses host footprint plus the greater of outstanding
reservations or observed direct-child footprint, plus the new reservation.
It treats the reservation sum and each admission atomically. A registered
direct-child PID can disappear between listing and sampling. A missing PID
contributes zero observed bytes while its reservation remains tied to cleanup.
The sample excludes escaped and unregistered descendants and other apps.
Sampling has no kernel enforcement. The configured estimate bounds admissions
and cannot cap allocations between observations. The project currently exports
traces, with no OTLP memory metrics or time-series leak detector.
