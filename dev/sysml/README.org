* Scope and ownership

The scope includes the plugin engine and the terminal client, their transport
boundaries, and their lifecycles. =project.sysml= selects the top-level views.
The files here own structural identities, relations, and state transitions.
Org owns rationale, protocol detail, assumptions, and evidence. The
Brief-to-Draft example stays in the RFC as a fixture of the generic contract.
The [[file:../../docs/40-rfcs/40.166-plugin-contract.org::#gambit-js-leverage][Gambit JS build target]] produces assets for the client boundary shown in
the transport view. The plugin request view models host execution.

The model follows the deterministic-engineering architecture content contract
at =1fe20380441a0cd85055695c2adcc55ce699a369=. It separates actual and target
elements, uses stable short IDs, states relation meaning, and traces each
requirement allocation to an owner and Org section. The reference project's
case and publication identities remain with that project.
[[https://github.com/hardenedlinux/deterministic-engineering/blob/1fe20380441a0cd85055695c2adcc55ce699a369/docs/10-19-design/10-architecture/10.31-architecture-document-and-decision-contracts.org][Architecture content contract]]

* Validate and render

model. Keep generated views paired with the source and OpenSysML version that
produced them. Edit the SysML source to change topology and the Org counterpart
to change rationale or evidence.
